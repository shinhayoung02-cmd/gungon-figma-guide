# GUNG:ON 검증 파트 정리
## 실제 관람 인사이트와 현재 솔루션의 정합성 검증 + 프로토타입 사용자 검증

> 프로젝트: **궁온 / GUNG:ON — 페르소나 체험형 경복궁 관람 시스템**  
> 목적: 기존 현장 관찰에서 발견한 문제와 현재 솔루션의 대응 관계를 먼저 점검하고, 이후 대표 관람 시퀀스를 프로토타입으로 구현하여 실제 사용자가 기획 의도대로 경험하는지 검증한다.

---

# 1. 검증의 목적

이번 검증은 단순히

> **“우리가 만든 해결안이 좋아 보이는가?”**

를 확인하는 것이 아니다.

서비스·경험디자인 이론서에서는 프로토타입 평가를

> **제안된 서비스가 초기 기획 의도와 가치를 제대로 구현하고 있는지 확인하고, 사용자와 이해관계자의 평가를 통해 실제 구현 전 품질과 성능을 확인하는 과정**

으로 설명한다. :contentReference[oaicite:0]{index=0}

따라서 궁온의 검증은 다음 두 단계로 진행한다.

### 1차 검증

**실제 관람 인사이트 ↔ 현재 솔루션 정합성 검증**

기존 현장 관찰과 Journey Map에서 발견한 문제가  
현재 궁온의 경험 구조와 직접 연결되어 있는지 확인한다.

### 2차 검증

**Prototype User Validation**

대표 관람 시퀀스를 실제 사용자가 경험했을 때

- 서비스의 의미를 이해하는지
- 각 터치포인트 사이의 연결을 자연스럽게 이해하는지
- 주요 과업을 스스로 수행할 수 있는지
- 경험의 의미가 실제로 전달되는지

를 확인한다.

---

# 2. 검증 기준

서비스·경험디자인 이론서에서 고객 여정 지도는  
사용자가 서비스를 경험하는 전체 과정을 단계별로 시각화하고,

- 생각
- 행동
- 감정
- 서비스 접점
- 강점
- 약점
- 기회 영역

을 통해 문제와 개선 가능성을 파악하는 방법으로 설명된다. :contentReference[oaicite:1]{index=1}

또한 사용자의 관점에서 서비스의 강점·약점·기회 요인을 파악하고,  
서비스 개선을 위한 우선순위를 판단하는 데 활용된다. :contentReference[oaicite:2]{index=2}

따라서 궁온은 기존 관람 조사에서 도출한 문제를 기준으로  
현재 솔루션의 필요성과 대응 관계를 다시 확인한다.

---

# 3. 1차 검증
# Insight–Solution 정합성 검증

## 검증 질문

> **기존 관람에서 발견한 문제가 현재 궁온의 경험 구조에서 실제로 해결되고 있는가?**

---

# 4. 실제 관람 인사이트

기존 현장 관찰에서는 다음과 같은 문제가 확인되었다.

### 정보와 공간의 연결 부족

- 설명판을 보더라도 얻을 수 있는 정보가 제한적이었다.
- 현장에서 공간의 역사적 맥락을 깊이 이해하기 어려웠다.
- 설명을 듣는 것과 실제 공간을 바라보는 경험이 분리되는 문제가 있었다.

기존 현장 관찰에서도 설명판의 정보가 제한적이고 현장에서 자체적으로 얻을 수 있는 정보가 부족한 문제가 기록되어 있다. :contentReference[oaicite:3]{index=3}

---

### 무엇을 중심으로 봐야 하는지 기준이 부족함

넓은 경복궁 공간을 자유롭게 관람할 수 있지만  
각 공간에서

> **무엇을 보고, 어떤 관점에서 이해해야 하는지**

에 대한 기준이 부족했다.

기존 Journey Map과 관찰 자료에서도 자율 관람에서 현재 위치와 방향 파악의 어려움, 관람 기준 부족 등이 확인되었다. :contentReference[oaicite:4]{index=4}

---

### 수동적인 관람 경험

기존 관람은

- 설명판 읽기
- 음성 안내 듣기
- 사진 촬영

등 정보 수용 중심으로 이루어졌다.

관람객이 공간의 의미와 연결된 행동을 직접 수행할 수 있는 체험 요소는 부족했다. 기존 관찰에서도 포토존 외 몰입하거나 참여할 수 있는 요소가 부족하고, 체류 시간 대비 기억에 남는 경험의 밀도가 낮다는 문제가 확인되었다. :contentReference[oaicite:5]{index=5}

---

### 관람 경험이 현장에서 끝남

관람이 끝난 뒤

- 무엇을 봤는지
- 어떤 내용을 이해했는지
- 어떤 경험을 했는지

다시 확인하거나 정리할 구조가 부족했다.

기존 프로젝트에서도 관람 후 내용을 다시 떠올리고 정리할 장치가 부족하다는 문제가 도출되었다. :contentReference[oaicite:6]{index=6}

---

# 5. Insight–Solution Validation Matrix

| 실제 관람에서 확인한 문제 | 필요한 경험 | 현재 궁온 솔루션 | 검증 질문 |
|---|---|---|---|
| 실제 공간과 역사 설명이 충분히 연결되지 않음 | 현재 보고 있는 공간과 역사 맥락을 함께 이해 | **Persona-based Interpretation + Historical Event** | 실제 공간을 보면서 그곳의 역사적 의미를 이해할 수 있는가? |
| 공간에서 무엇을 중심으로 봐야 할지 기준이 부족함 | 관람의 관점과 주목 지점 제공 | **Persona Select + Focus Point** | 선택한 인물의 관점과 Focus Point가 공간을 바라보는 기준으로 작동하는가? |
| 읽고 듣는 방식 중심의 수동적 관람 | 공간의 기능과 연결된 직접 행동 | **오늘의 수라상 + 훈민정음 서재** | 직접 행동하는 과정이 공간의 기능과 역사적 의미 이해로 이어지는가? |
| 현장에서 발생한 경험이 각각 따로 끝날 가능성 | 경험 간 연결과 결과 축적 | **Smart Glass → Interactive Screen → Web** | 각각의 터치포인트가 별도의 기기가 아니라 하나의 관람 흐름으로 인식되는가? |
| 관람 이후 경험을 다시 확인하기 어려움 | 관람 결과 기록 및 회상 | **Web Record** | 관람 이후 어떤 공간과 프로그램을 경험했는지 다시 확인할 수 있는가? |
| 현장의 경험이 일상으로 이어지지 않음 | 경험 결과의 선택적 확장 | **Custom Goods** | 굿즈가 단순 상품이 아니라 자신의 관람 결과를 이어가는 매체로 이해되는가? |

# 6. 1차 검증 결과에서 확인할 것

1차 검증에서는 각 기능의 존재 여부를 확인하는 것이 아니라  
다음 세 가지를 확인한다.

### 01. 문제 대응성

> 이 솔루션이 기존 관람에서 확인한 문제에 직접 대응하고 있는가?

---

### 02. 기능의 존재 이유

> 이 기능이 없다면 어떤 사용자 문제가 다시 발생하는가?

각 기능이 단순히 재미를 추가하기 위한 기능이 아니라  
기존 관람 문제에서 출발했는지 확인한다.

---

### 03. 전체 경험과의 연결

> 각 해결안이 개별 기능으로 끝나지 않고 다음 경험과 연결되는가?

예:

**공간 해석**
→ **직접 체험**
→ **결과 생성**
→ **기록**
→ **관람 후 리마인드**

---

# 7. 1차 검증을 통해 정리해야 하는 서비스 구조

검증 후 궁온의 경험은 다음 구조로 연결되어야 한다.

**준비**
→ **해석**
→ **체험**
→ **기록**
→ **확장**

각 단계가 다음 단계의 이유가 되어야 한다.

---

## 준비 → 해석

WEB에서 서비스의 이용 방식을 이해한 뒤  
현장에서 Smart Glass 경험을 시작한다.

---

## 해석 → 체험

Smart Glass에서 공간과 역사적 맥락을 이해한 뒤  
그 공간의 기능과 연결된 행동을 Interactive Screen에서 직접 수행한다.

---

## 체험 → 기록

Interactive Screen에서 만들어진 체험 결과가  
Web의 개인 관람 기록으로 이어진다.

---

## 기록 → 확장

Web에 저장된 경험 결과를 다시 확인하고,  
원하는 경우 Custom Goods를 통해 개인화된 실물로 확장한다.

---

## 확장 → 리마인드

Web Record와 Custom Goods를 통해  
관람 이후에도 경복궁에서의 경험을 다시 떠올린다.

---

# 8. 2차 검증
# Prototype User Validation

1차 정합성 검증만으로

> **“궁온이 실제 사용자에게 효과적이다”**

라고 판단할 수는 없다.

서비스·경험디자인 이론서에서는  
서비스 프로토타입을 통해 초기 기획 의도와 가치가 실제 사용자 경험에서 구현되는지 평가하도록 설명한다. :contentReference[oaicite:7]{index=7}

따라서 다음 단계에서는  
궁온의 대표 Experience Sequence를 프로토타입으로 구현하여 실제 사용자 평가를 진행한다.

---

# 9. Prototype Validation Goal

프로토타입 검증의 핵심 질문은 다음과 같다.

### Q1. 이해도

> 사용자는 별도의 설명 없이 현재 경험의 의미를 이해할 수 있는가?

---

### Q2. 연결성

> 사용자는 Web → Smart Glass → Interactive Screen → Web의 관계를 하나의 경험으로 이해하는가?

---

### Q3. 과업 수행

> 사용자는 각 단계에서 필요한 행동을 스스로 완료할 수 있는가?

---

### Q4. 역사적 의미 전달

> 사용자는 체험 행동을 단순 인터랙션이 아니라 공간의 역사적 맥락과 연결하여 이해하는가?

---

### Q5. 관람 후 확장

> 사용자는 Web Record와 Custom Goods를 관람 이후 경험을 이어주는 요소로 이해하는가?

---

# 11. 사용자 검증 과업

## TASK 01
## 관람 관점 이해

### 사용자 과업

> **왕의 시선으로 현재 공간을 관람해보세요.**

### 확인 항목

- 왕 / 왕비 / 세자 선택의 의미를 이해하는가?
- 현재 보고 있는 공간과 페르소나의 관계를 이해하는가?
- Persona-based Interpretation을 자연스럽게 읽고 이해하는가?
- Historical Event와 Persona Interpretation의 역할을 구분하는가?
- Focus Point를 통해 실제 공간에서 무엇을 봐야 하는지 알 수 있는가?

### 검증 목표

> **페르소나가 단순 캐릭터 선택이 아니라 공간을 바라보는 관점으로 작동하는지 확인한다.**

---

# 12. TASK 02
# 공간 이해 → 직접 체험

### 사용자 과업

> **이 공간과 연결된 체험을 찾아 완료해보세요.**

### 확인 항목

- Smart Glass의 프로그램 도착 안내를 이해하는가?
- 왜 이 공간에서 이 프로그램을 해야 하는지 이해하는가?
- Smart Glass를 벗고 Interactive Screen을 사용하는 전환이 자연스러운가?
- 프로그램의 행동과 공간의 기능을 연결하는가?

### 검증 목표

> **Smart Glass에서 얻은 공간 이해가 Interactive Screen의 행동으로 자연스럽게 이어지는지 확인한다.**

---

# 13. TASK 03
# 체험 → 결과 → 기록

### 사용자 과업

> **방금 완료한 체험의 결과를 다시 확인해보세요.**

### 확인 항목

- 체험이 완료되었다는 것을 인지하는가?
- 결과가 어디에 저장되는지 이해하는가?
- Web에서 자신의 프로그램 결과를 찾을 수 있는가?
- Screen과 Web이 연결되어 있다고 인식하는가?

### 검증 목표

> **현장에서 발생한 행동이 개인의 관람 기록으로 연결된다는 구조를 이해하는지 확인한다.**

---

# 14. TASK 04
# 관람 기록 이해

### 사용자 과업

> **오늘 어떤 공간과 프로그램을 경험했는지 확인해보세요.**

### 확인 항목

- 선택한 페르소나를 확인할 수 있는가?
- 경험한 공간을 확인할 수 있는가?
- 완료한 프로그램을 찾을 수 있는가?
- 각 프로그램의 결과를 다시 볼 수 있는가?

### 검증 목표

> **현장의 여러 경험이 Web에서 하나의 나의 관람 기록으로 통합되는지 확인한다.**

---

# 15. TASK 05
# 관람 후 경험 확장

### 사용자 과업

> **오늘의 체험 결과를 관람 이후에도 남기고 싶다면 어떻게 할 것 같나요?**

### 확인 항목

- Web에서 기록을 다시 확인할 수 있다는 것을 이해하는가?
- Custom Goods Preview를 발견할 수 있는가?
- 굿즈에 자신의 체험 결과가 반영된다는 것을 이해하는가?
- 굿즈 구매가 필수가 아닌 선택 사항이라는 것을 이해하는가?
- 굿즈를 단순 기념품이 아닌 경험의 연장으로 인식하는가?

### 검증 목표

> **현장 경험이 기록과 개인화된 결과를 통해 일상으로 확장되는 구조가 자연스럽게 전달되는지 확인한다.**

---

# 16. 평가 지표

서비스·경험디자인 이론서에서는 사용성 평가의 주요 기준을

- 유용성
- 효율성
- 만족도

로 정리하고,

- 과업 성공률
- 과업 완료 시간
- 오류
- 사용자 만족도
- 사용자 의견

등을 평가 데이터로 활용할 수 있다고 설명한다. :contentReference[oaicite:8]{index=8}

궁온에서는 이를 프로젝트 특성에 맞게 다음과 같이 적용한다.

| 평가 영역 | 확인 내용 | 확인 방법 |
|---|---|---|
| **과업 성공률** | 도움 없이 주요 경험을 완료할 수 있는가 | 성공 / 부분 성공 / 실패 |
| **이해도** | 현재 제공되는 콘텐츠와 행동의 의미를 이해하는가 | 과업 후 질문 |
| **연결성** | Glass → Screen → Web 관계를 하나의 경험으로 인식하는가 | 관찰 + 인터뷰 |
| **효율성** | 다음 행동을 찾기 위해 불필요하게 헤매지 않는가 | 완료 시간 / 되돌아가기 / 탐색 행동 |
| **오류** | 잘못 이해하거나 잘못 이동하는 지점이 있는가 | 오류 발생 위치 기록 |
| **역사적 의미 이해** | 체험 행동과 공간의 역사적 기능을 연결하는가 | 과업 후 설명 요청 |
| **기억성** | 체험 이후 어떤 인물·공간·행동이 기억나는가 | 사후 질문 |
| **만족도** | 전체 경험을 자연스럽고 의미 있게 느끼는가 | 5점 척도 + 이유 |
| **확장성 이해** | Record와 Goods의 관람 후 역할을 이해하는가 | 인터뷰 |

※ `이해도`, `연결성`, `역사적 의미 이해`, `기억성`, `확장성 이해`는 궁온의 서비스 목적에 맞춰 추가한 프로젝트별 평가 항목이다.

# 19. 핵심 검증 포인트

궁온에서 가장 중요하게 확인해야 하는 것은  
각 화면의 사용성이 아니라 **전체 경험의 연결성**이다.

따라서 아래 네 가지를 우선적으로 검증한다.

---

## 01. Persona가 관람의 시선으로 작동하는가?

단순한 캐릭터 선택이 아니라

> **“이 인물의 관점으로 이 공간을 보고 있다”**

는 경험이 형성되어야 한다.

---

## 02. 공간 이해가 행동으로 이어지는가?

Smart Glass에서 정보를 보고 끝나는 것이 아니라

> **공간 이해 → 직접 행동**

으로 이어져야 한다.

---

## 03. 행동이 기록으로 이어지는가?

Interactive Screen의 프로그램이 일회성 체험으로 끝나지 않고

> **행동 → 결과 → Web Record**

로 연결되어야 한다.

---

## 04. 기록이 관람 이후까지 이어지는가?

관람 종료와 동시에 경험이 끝나는 것이 아니라

> **기록 → 다시 보기 → 선택적 Goods → Reminder**

로 이어져야 한다.

---

# 20. 서비스 접점 간 연결 검증

서비스·경험디자인 이론서에서는 서비스 접점을  
사용자가 서비스를 경험하는 과정에서 만나는 물리적 요소, 상호작용, 커뮤니케이션 등의 모든 접촉점으로 설명한다. 또한 서비스 청사진은 사용자 여정, 서비스 접점, 후방 절차를 함께 시각화하는 서비스의 마스터플랜으로 정의한다. :contentReference[oaicite:10]{index=10}

따라서 궁온에서는 각각의 터치포인트 자체보다  
**터치포인트 사이의 Handoff가 자연스러운지**를 검증한다.

| 연결 구간 | 검증할 내용 |
|---|---|
| **WEB → SMART GLASS** | 웹에서 이해한 서비스가 현장 경험 시작으로 자연스럽게 이어지는가 |
| **SMART GLASS → SCREEN** | 공간을 이해한 뒤 직접 행동해야 하는 이유가 자연스러운가 |
| **SCREEN → WEB** | 체험 결과가 개인 기록으로 저장된다는 것을 이해하는가 |
| **SMART GLASS → WEB** | 현장에서 경험한 공간과 페르소나가 관람 기록으로 연결되는가 |
| **WEB → GOODS** | 기록된 결과가 굿즈 개인화에 사용된다는 것을 이해하는가 |
| **WEB / GOODS → DAILY LIFE** | 관람 이후 경험을 다시 떠올리는 구조로 인식되는가 |

로 끝내지 않는다.

- 긴 완료 시간

등을 통해 사용성 이슈를 식별하도록 설명한다. :contentReference[oaicite:11]{index=11}

| 예: 체험 결과 저장 위치를 찾지 못함 | Web 진입 후 결과 메뉴 탐색 반복 | Result → Web 연결 표현 부족 | 완료 시 Web 기록 연결 피드백 추가 |

# 28. 검증 파트 핵심 원칙

궁온의 검증은

> **기능이 작동하는가**

에서 끝나지 않는다.

> **사용자가 인물의 시선으로 공간을 이해하고, 그 이해가 직접 행동으로 이어지며, 행동의 결과가 기록되어 관람 이후까지 하나의 경험으로 연결되는가**

이다.

이것이 이번 GUNG:ON 서비스 검증의 핵심 기준이다.
