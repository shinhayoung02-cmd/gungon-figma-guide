# 2. 서비스 원칙
# SERVICE PRINCIPLES

서비스 원칙은 기능 목록이 아니다.

새로운 기능이나 화면을 결정할 때

> **“이 기능이 궁온다운가?”**

를 판단하기 위한 공통 기준이다.

현재 궁온은 다음 5개의 서비스 원칙을 기준으로 한다.

---

# PRINCIPLE 01
# SPACE FIRST
## 화면보다 실제 경복궁을 먼저 본다

궁온의 경험 중심은 디지털 화면이 아니라 **실제 경복궁 공간**이다.

Smart Glass와 Interactive Screen은 실제 공간을 대체하는 것이 아니라 사용자가 공간을 더 잘 바라보고 이해하도록 보조해야 한다.

### 적용 기준

- 이동 중 Smart Glass 정보량을 최소화한다.
- 실제 전각을 가리는 과도한 그래픽을 사용하지 않는다.
- 콘텐츠는 현재 공간과 직접 관계있는 정보만 제공한다.
- 사용자의 시선이 화면에 오래 머물지 않도록 한다.
- Interactive Screen은 특정 프로그램 공간에서만 집중적으로 사용한다.
- 체험이 끝나면 다시 실제 경복궁 관람으로 복귀한다.

### 판단 질문

> 이 기능이 사용자를 경복궁 공간에 더 집중하게 하는가, 아니면 화면에 더 집중하게 하는가?

---

# PRINCIPLE 02
# PERSPECTIVE FIRST
## 정보보다 관점을 먼저 제공한다

궁온은 일반적인 역사정보 안내 서비스가 아니다.

사용자가 왕 · 왕비 · 세자 중 하나의 인물을 선택하고  
그 인물과 공간의 관계를 통해 경복궁을 바라보도록 한다.

### 적용 기준

Smart Glass 콘텐츠는 다음 세 축을 구분한다.

```text
PERSONA-BASED INTERPRETATION
누구의 시선으로 볼 것인가

+

HISTORICAL EVENT
이 공간에서 무슨 일이 있었는가

+

FOCUS POINT
무엇을 주목해서 볼 것인가
```

### AI 적용 원칙

AI가 역사적 사실을 임의로 생성하지 않는다.

```text
전문가 검수 역사 콘텐츠
↓
현재 공간 인지
↓
선택한 Persona 확인
↓
관련 콘텐츠 선택 · 구성
↓
사용자에게 제공
```

### 판단 질문

> 이 콘텐츠가 단순 정보를 하나 더 보여주는 것인가, 아니면 공간을 바라보는 새로운 기준을 제공하는가?

---

# PRINCIPLE 03
# UNDERSTAND → ACT
## 이해한 내용은 행동으로 이어진다

궁온의 경험은 설명을 읽거나 보는 것에서 끝나지 않는다.

Smart Glass를 통해 이해한 공간의 의미를  
Interactive Screen에서 직접 행동하면서 경험하게 한다.

### 경험 구조

```text
SEE
실제 공간을 본다

↓

UNDERSTAND
인물의 시선과 역사적 맥락을 이해한다

↓

DO
공간과 연결된 행동을 직접 수행한다

↓

RESULT
나의 체험 결과가 생성된다
```

### 적용 기준

Interactive Screen 프로그램은

- 단순 퀴즈
- 정보 확인
- 영상 시청

으로 끝나지 않는다.

반드시

- 선택
- 조작
- 쓰기
- 배치

중 하나 이상의 직접 행동을 포함한다.

### 판단 질문

> 사용자가 방금 이해한 역사적 맥락이 이 행동과 연결되어 있는가?

---

# PRINCIPLE 04
# CONNECTED CONTINUITY
## 하나의 경험은 다음 경험으로 이어진다

WEB / SMART GLASS / INTERACTIVE SCREEN을 각각 독립적인 기기로 설계하지 않는다.

한 접점에서 만들어진 경험과 결과가 다음 접점의 맥락으로 이어져야 한다.

### 핵심 연결

```text
WEB
서비스 이해

↓

SMART GLASS
공간 해석

↓

INTERACTIVE SCREEN
직접 행동

↓

WEB
관람 기록

↓

CUSTOM GOODS
선택적 실물 확장

↓

DAILY LIFE
경험 리마인드
```

### 적용 기준

- 각 접점에는 명확한 주 역할이 있다.
- 동일한 기능을 여러 접점에서 반복하지 않는다.
- 다음 접점으로 이동해야 하는 이유가 사용자에게 이해되어야 한다.
- 프로그램 결과는 관람 후 다시 확인할 수 있어야 한다.
- 기기 변경이 경험 단절로 느껴지지 않아야 한다.

### 판단 질문

> 이 경험이 끝난 뒤 사용자는 자연스럽게 다음 행동을 이해할 수 있는가?

---

# PRINCIPLE 05
# RESPECT THE VISIT
## 역사와 사용자의 선택을 존중한다

궁온은 게임처럼 모든 콘텐츠를 완료하게 만드는 서비스가 아니다.

사용자가 자신의 속도로 실제 경복궁을 관람할 수 있도록 한다.

### 적용 기준

- Program 참여는 선택 사항이다.
- Custom Goods 구매는 선택 사항이다.
- 모든 공간을 방문하도록 강제하지 않는다.
- Digital Stamp / 엽전 수집을 사용하지 않는다.
- 경험을 완료하기 위한 점수 경쟁을 만들지 않는다.
- 역사적 사실은 전문가 검수를 기준으로 한다.
- 실제 문화유산 공간을 훼손하거나 관람을 방해하는 설치를 하지 않는다.
- 이동 중 안전을 해칠 정도의 정보나 인터랙션을 제공하지 않는다.

### 판단 질문

> 이 기능은 사용자의 선택과 실제 문화유산 경험을 존중하고 있는가?

# 4. 서비스 시나리오
# SERVICE SCENARIO

서비스 시나리오는 User Flow와 다르다.

User Flow가 화면이나 기능의 이동 순서를 정의한다면  
서비스 시나리오는

> **사용자가 어떤 상황에서 무엇을 생각하고 행동하며 서비스를 경험하는지**

를 이야기 형태로 구체화한다.

궁온의 시나리오는 세 단계로 관리한다.

```text
01 CONTEXT SCENARIO
이상적인 전체 경험

↓

02 KEY PATH SCENARIO
실제 서비스 이용 순서

↓

03 VALIDATION SCENARIO
문제 상황과 예외 대응
```

# 5. Persona 용어 구분

궁온에는 두 종류의 Persona 개념이 혼동될 수 있으므로 구분한다.

## User Persona

서비스디자인에서 사용하는 실제 사용자 유형.

예:

```text
새로운 방식으로 경복궁을 경험하고 싶은 관람객
재방문 관람객
역사적 공간을 직접 체험하며 이해하고 싶은 관람객
```

## Historical Persona

궁온 서비스 안에서 사용자가 선택하는 역사적 관점.

```text
왕
왕비
세자
```

서비스 시나리오는 **User Persona의 관점에서 작성하고**,  
시나리오 안에서 Historical Persona를 선택하도록 한다.

# 6. 정황 시나리오
# CONTEXT SCENARIO

## 목적

궁온이 이상적으로 작동했을 때  
사용자가 어떤 경험을 하게 되는지 큰 그림을 보여준다.

---

## 대표 시나리오

경복궁을 방문한 관람객은 방문 전에 궁온 웹을 통해 이 서비스가 단순한 디지털 해설이 아니라 역사 속 인물의 시선으로 실제 경복궁을 바라보고 특정 공간에서는 직접 행동을 체험하는 서비스라는 것을 확인한다.

경복궁에 도착한 뒤 현장에서 Smart Glass를 대여하고 착용한다.

관람객은 이번 관람에서 경복궁을 바라볼 인물로 **왕**을 선택한다.

관람을 시작하면 Smart Glass는 현재 사용자가 바라보고 있는 전각을 인지하고, 왕과 이 공간이 어떤 관계를 가지고 있었는지 보여준다.

관람객은 단순한 건축 설명이 아니라

- 왕의 관점에서 공간이 어떤 의미였는지
- 이곳에서 어떤 역사적 사건이 있었는지
- 실제 공간에서 무엇을 주목해서 봐야 하는지

를 확인하며 공간을 바라본다.

프로그램이 연결된 공간에 도착하면 Smart Glass가 프로그램이 있다는 사실을 알려준다.

사용자가 참여를 선택하면 Interactive Screen으로 이동한다.

Interactive Screen에서는 Smart Glass에서 이해했던 역사적 맥락과 연결된 행동을 직접 수행한다.

예를 들어

- 오늘의 수라상에서는 왕실 음식과 상차림을 선택하고 배치하며
- 훈민정음 서재에서는 직접 쓰고 조작하는 과정을 경험한다.

프로그램을 완료하면 자신의 선택과 행동에 따른 체험 결과가 만들어진다.

이 결과는 현장에서 한 번 보고 끝나는 것이 아니라 WEB의 나의 관람 기록에 저장된다.

관람객은 다시 Smart Glass를 통해 실제 경복궁 관람으로 돌아간다.

관람이 끝난 뒤 Smart Glass를 반납하고 WEB에서

- 오늘 선택한 Persona
- 경험한 공간
- 완료한 프로그램
- 프로그램별 결과

를 다시 확인한다.

원하는 경우 자신의 Persona와 프로그램 결과가 적용된 Custom Goods를 미리 확인하고 선택적으로 구매할 수 있다.

관람 이후에도 WEB의 기록과 Goods를 통해 그날의 경복궁 경험을 다시 떠올릴 수 있다.

# 8. 주요 경로 시나리오
# KEY PATH SCENARIO

정황 시나리오를 실제 사용 과정 단위로 구체화한다.

| 단계 | 사용자 행동 | Touchpoint | 서비스 반응 | 다음 경험으로 이어지는 이유 |
|---|---|---|---|---|
| 01 서비스 이해 | 궁온 서비스와 이용 방법 확인 | WEB | 서비스 개념·이용 방식 제공 | 현장에서 무엇을 경험할지 이해 |
| 02 현장 도착 | Smart Glass 대여 | Physical / Staff | 장비 상태 및 기본 사용 안내 | 현장 경험 시작 |
| 03 Persona 선택 | 왕·왕비·세자 중 선택 | SMART GLASS | 선택한 인물 소개 | 관람 관점 설정 |
| 04 공간 인지 | 실제 전각을 바라봄 | SMART GLASS | 현재 공간 인지 | 공간 맥락 제공 |
| 05 Persona 해석 | 인물과 공간 관계 확인 | SMART GLASS | Persona Interpretation | 누구의 시선인지 이해 |
| 06 Historical Event | 해당 공간 사건 확인 | SMART GLASS | 검수된 역사 콘텐츠 제공 | 공간의 시간적 맥락 이해 |
| 07 Focus Point | 실제 공간의 특정 지점 관찰 | SMART GLASS + Physical Space | 주목할 대상 강조 | 화면에서 다시 실제 공간으로 시선 이동 |
| 08 Program 안내 | 프로그램 존재 확인 | SMART GLASS | 도착 / 참여 가능 안내 | 이해에서 행동으로 전환 |
| 09 프로그램 참여 | 선택·조작·쓰기·배치 | INTERACTIVE SCREEN | 행동에 따른 피드백 | 체험 결과 생성 |
| 10 결과 확인 | 나의 결과 확인 | SCREEN | Program Result 제공 | 행동의 결과 확인 |
| 11 기록 | 결과 저장 | SYSTEM → WEB | 관람 기록 반영 | 현장 행동이 기록으로 이어짐 |

| 15 선택적 확장 | Goods Preview 확인 | WEB | 결과 기반 개인화 미리보기 | 디지털 경험을 실물로 확장 |

# 9. 주요 경로의 반복 구조

경복궁 관람 중에는 아래 Core Loop가 반복된다.

```text
공간 진입

↓

현재 공간 인지

↓

Persona Interpretation

↓

Historical Event

↓

Focus Point

↓

[Program이 있는 경우]

Program 안내

↓

Interactive Experience

↓

Result
```

Program이 없는 공간에서는

```text
↓

```

으로 이어진다.

즉 모든 공간에 Program을 강제하지 않는다.

# 10. 검증 시나리오
# VALIDATION SCENARIO

검증 시나리오는 이상적인 흐름이 깨졌을 때 서비스가 어떻게 대응하는지를 정의한다.

---

## CASE 01
## Smart Glass가 현재 공간을 인식하지 못함

### 상황

사용자가 특정 전각에 진입했지만 공간 인식이 정상적으로 이루어지지 않는다.

### 문제

잘못된 콘텐츠가 제공되면 역사적 경험에 대한 신뢰가 무너진다.

### 대응 원칙

```text
공간 인식 실패

↓

잘못된 콘텐츠 제공 금지

↓

기본 관람 상태 유지

↓

재인식 시도

↓

지속 실패 시 최소 안내 제공
```

### 핵심

> 확신할 수 없는 역사 콘텐츠를 임의로 제공하지 않는다.

---

## CASE 02
## Interactive Screen이 사용 중임

### 상황

Program 공간에 도착했지만 다른 사용자가 Screen을 이용하고 있다.

### 문제

관람 흐름이 강제로 멈출 수 있다.

### 대응

- Program 참여를 강제하지 않는다.
- 기다림을 요구하지 않는다.
- 현재 공간 관람을 계속할 수 있게 한다.
- 사용자가 원하면 이후 다시 참여할 수 있도록 한다.

### 핵심

> Program 때문에 경복궁 전체 관람 흐름을 막지 않는다.

---

## CASE 03
## 사용자가 Program을 원하지 않음

### 상황

Program 안내를 받았지만 참여하고 싶지 않다.

### 대응

```text
Program 발견

↓

참여 / 건너뛰기

↓

건너뛰기 선택

↓

Smart Glass 관람 지속
```

### 핵심

> Program은 필수 미션이 아니다.

---

## CASE 04
## Program 체험 도중 중단

### 상황

사용자가 체험을 중간에 종료한다.

### 대응 원칙

- 완료된 것으로 표시하지 않는다.
- 불완전한 결과를 완성 결과처럼 기록하지 않는다.
- 이후 재시작 가능 여부는 Program 정책에서 정의한다.

---

## CASE 05
## Program 결과가 WEB에 표시되지 않음

### 상황

체험을 완료했지만 Web Record에 결과가 나타나지 않는다.

### 대응 구조

```text
Program 완료

↓

Result 생성

↓

서비스 시스템 저장

↓

관람 세션과 결과 매칭

↓

WEB Record 반영
```

어느 단계에서 문제가 발생했는지 운영 시스템에서 확인할 수 있어야 한다.

### 중요

WEB과 Smart Glass를 사용자가 직접 연결하거나 관리하는 기능은 만들지 않는다.

다만 여러 Touchpoint의 결과를 하나의 관람 기록으로 이어주기 위해서는  
**서비스 차원의 관람 세션 식별 방식**이 필요하다.

구체적인 식별 방식은 현재 미확정이다.

검토 가능 방식:

- 현장 이용권 기반 ID
- QR 기반 Session ID
- 임시 관람 코드
- Web 로그인 계정

중 하나를 향후 운영 설계에서 결정한다.

---

## CASE 06
## Smart Glass 장비 오류

### 대응

```text
오류 확인
↓
사용자 경험 중단 최소화
↓
현장 운영 인력 지원
↓
필요 시 장비 교체
↓
기존 관람 세션 복원 여부 확인
```

## CASE 07
## Goods를 구매하지 않음

아무런 불이익이 없다.

WEB의 관람 기록만으로 서비스 경험은 완결된다.

Custom Goods는

> 관람 경험을 더 오래 남기고 싶은 사용자를 위한 선택형 확장

으로만 운영한다.

# 11. 터치포인트 연결성
# CONNECTED TOUCHPOINTS

궁온에서 Touchpoint는 각각 독립된 제품이 아니다.

서비스 경험의 특정 순간을 담당하는 접점이다.

따라서 중요한 것은

> **무엇이 어디에 있는가**

뿐 아니라

> **한 접점에서 만들어진 맥락과 결과가 다음 접점에서 어떻게 사용되는가**

이다.

# 12. Touchpoint 역할

## WEB

### Primary Role

```text
안내
+
현황
+
기록
+
관람 후 확장
```

- Smart Glass 연결 관리
- 실시간 지도 관제
- 직접 역사 체험

```text
선택
```

- Persona Select
- Persona Interpretation

- Focus Point
- Program Arrival

### Primary Role

```text
직접 행동
+

```

### 핵심 행동

- 선택
- 조작
- 쓰기
- 배치
- 결과 확인

### Primary Role

```text
관람 결과의 물리적 확장

일상 Reminder
```

# 13. Handoff 01
# WEB → SMART GLASS

## 연결되는 것

```text
서비스에 대한 이해
→
현장 경험
```

WEB에서 사용자는

- 궁온이 어떤 서비스인지
- 현장에서 Smart Glass를 사용한다는 것
- Persona 관점으로 공간을 본다는 것
- 특정 공간에서 직접 체험할 수 있다는 것

을 이해한다.

현장에서는 별도의 기기 연결 작업 없이 Smart Glass를 대여하여 경험을 시작한다.

### 사용자에게 보여야 하는 신호

> 이제 현장에서 Smart Glass를 착용하고 관람을 시작하세요.

### 연결 목적

**기능 연결이 아니라 기대와 경험의 연결**

---

# 14. Handoff 02
# SMART GLASS → INTERACTIVE SCREEN

## 연결되는 것

```text
공간 이해
→
행동
```

SMART GLASS

```text
이 공간은 어떤 곳인가
↓
이곳에서 어떤 일이 있었는가
↓
무엇을 봐야 하는가
```

INTERACTIVE SCREEN

```text
그 공간과 연결된 행동을 직접 수행
```

```text
Program 도착
+
Program 이름
+
짧은 행동 안내
```

### 연결 목적

> 보고 이해한 역사를 직접 행동으로 경험한다.

# 15. Handoff 03
# INTERACTIVE SCREEN → WEB

## 연결되는 것

```text
행동
→
결과
→
기록
```

Interactive Screen에서 만든 결과를 Web에서 다시 확인한다.

### 전달되는 정보

- Program 이름
- 완료 상태
- 체험 결과
- 필요 시 개인화 결과 데이터

### 사용자에게 보여야 하는 신호

> 체험 결과가 나의 관람 기록에 저장되었습니다.

### 연결 목적

> 현장의 행동이 사라지지 않도록 한다.

---

# 16. Handoff 04
# SMART GLASS → WEB

## 연결되는 것

```text
현장 경험
→
관람 기록
```

Web에서 확인 가능한 정보

- 오늘 선택한 Persona
- 경험한 주요 공간
- 완료한 Program
- Program Result

### 주의

궁온은 GPS 전체 이동 로그를 핵심 경험으로 만들지 않는다.

따라서

```text
정확한 이동 궤적
체류 시간 랭킹
실시간 위치 추적 기록
```

등을 주요 기능으로 포함하지 않는다.

핵심은

> **어떤 역사적 공간과 경험을 만났는가**

이다.

```text
SUPPORT PROCESS
```

## SLIDE 01
# SERVICE PRINCIPLES

### 대제목

**실제 공간을 중심으로, 이해가 행동과 기록으로 이어지도록 설계했습니다**

### 내용

```text
SPACE FIRST

PERSPECTIVE FIRST

UNDERSTAND → ACT

CONNECTED CONTINUITY

RESPECT THE VISIT
```

---

## SLIDE 02
# SERVICE SCENARIO

### 대제목

**방문 전부터 관람 이후까지 하나의 경험 시나리오로 연결했습니다**

### 내용

```text
서비스 이해

→ Persona 선택

→ 공간 해석

→ 역사적 사건

→ 직접 체험

→ 결과 생성
```

```text
Context Scenario

Validation Scenario
```

### 대제목

```text
↓

↓

기록을 일상으로

↓

GOODS / REMINDER
```

# SERVICE BLUEPRINT

# 34. 최종 핵심 문장

> **궁온은 WEB, SMART GLASS, INTERACTIVE SCREEN을 각각 제공하는 서비스가 아니라, 실제 경복궁을 중심으로 ‘관점을 선택하고 → 공간을 이해하고 → 직접 행동하고 → 결과를 기록하고 → 관람 이후 다시 떠올리는’ 하나의 연속된 경험 시스템이다.**
