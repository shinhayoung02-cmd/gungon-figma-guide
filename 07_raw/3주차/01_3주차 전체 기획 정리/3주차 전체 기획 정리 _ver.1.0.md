# GUNG:ON 3주차 변경사항 정리
## 서비스 디자인 · 시퀀스 · 연결성 · 확장성 · 검증 · 브랜딩

> 프로젝트: **궁온 / GUNG:ON — 페르소나 체험형 경복궁 관람 시스템**  
> 목적: 교수님 피드백을 반영하여 이번 주차에 수정해야 할 서비스 디자인과 브랜딩 내용을 정리한다.

---

# 1. 3주차 핵심 변경 방향

이번 주차의 핵심은 새로운 기능을 추가하는 것이 아니라,  
**현재 서비스의 경험 구조를 다시 정리하고 각 경험이 서로 어떻게 연결되는지 보여주는 것**이다.

기존에는 서비스를

- WEB
- SMART GLASS
- INTERACTIVE SCREEN
- CUSTOM GOODS

처럼 **터치포인트 기준**으로 분류했다.

하지만 이 방식은 각 기기에서 무엇을 하는지는 잘 보이지만,

- 방문객이 어떤 순서로 경험하는지
- 각 경험이 다음 단계로 어떻게 이어지는지
- 터치포인트 사이에서 어떤 정보와 경험이 연결되는지
- 관람 이후 경험이 어떻게 지속되는지

가 충분히 드러나지 않는다.

따라서 이번 주차부터는 발표에서

**터치포인트 중심 → 사용자 경험 단계 중심**

으로 서비스 구조를 다시 정리한다.

---

# 2. 서비스 분류 방식 변경

## 기존 방식

```text
WEB
SMART GLASS
INTERACTIVE SCREEN
CUSTOM GOODS
```

기기와 기능을 기준으로 각각 분리하여 설명했다.

### 기존 방식의 문제

- 기기 중심으로 보임
- 서비스 전체 경험보다 기능 목록처럼 보일 수 있음
- 터치포인트 사이의 연결 관계가 약함
- 사용자가 실제로 어떤 순서로 경험하는지 한눈에 보이지 않음
- 관람 전 · 중 · 후의 흐름이 끊겨 보임

---

## 변경 방식

서비스를 사용자가 경험하는 단계에 따라 다음과 같이 재분류한다.

```text
01 준비 [관람을 준비하다]
관람 방식을 이해하고 준비

↓

02 해석 [인물의 시선으로 궁을 이해하다]
인물의 시선으로 실제 공간을 이해

↓

03 체험 [체험을 통해 궁을 이해하다]
공간과 연결된 행동을 직접 수행

↓

04 기록 · 리마인드 [현장의 경험을 일상으로 이어가다]
현장의 경험을 기록하고 관람 이후까지 이어감
```

---

# 3. 경험 단계별 서비스 구조

## 01. 준비

### 사용자 목적

궁온이 어떤 서비스인지 이해하고 현장 경험을 준비한다.

### 주요 경험

- 서비스 안내 확인
- 이용 방법 확인
- 언어 및 접근성 확인

### 주요 터치포인트

**WEB**

### 핵심 문장

> 관람 전, 웹에서 궁온의 이용 방식과 경험 구조를 이해합니다.

---

## 02. 해석

### 사용자 목적

실제 경복궁 공간을 선택한 인물의 시선으로 바라보고 이해한다.

### 주요 경험

- 왕 / 왕비 / 세자 중 페르소나 선택
- 현재 전각 인지
- 페르소나와 공간의 관계 확인
- 페르소나 기반 공간 해석
- 현재 공간의 역사적 사건 확인
- Focus Point 확인

### 주요 터치포인트

**SMART GLASS**

### 핵심 문장

> 선택한 인물의 시선으로 실제 경복궁 공간과 그곳의 역사를 바라봅니다.

---

## 03. 체험

### 사용자 목적

스마트 글라스를 통해 이해한 공간의 기능과 맥락을 직접 행동으로 경험한다.

### 주요 경험

- 선택
- 조작
- 쓰기
- 배치
- 결과 확인

### 대표 프로그램

- 오늘의 수라상
- 훈민정음 서재

### 주요 터치포인트

**INTERACTIVE SCREEN**

### 핵심 문장

> 보고 이해한 공간의 의미를 직접 행동하며 경험합니다.

---

## 04. 기록 · 확장

### 사용자 목적

현장에서 만들어진 경험을 기록하고 관람 이후에도 다시 이어간다.

### 주요 경험

- 완료한 프로그램 확인
- 프로그램 결과 확인
- 나의 관람 기록 확인
- 체험 결과 다시 보기
- 커스텀 굿즈 미리보기
- 선택 구매
- 일상에서 경험 리마인드

### 주요 터치포인트

**WEB + CUSTOM GOODS**

### 핵심 문장

> 현장에서 만든 경험을 기록하고, 관람 이후 일상까지 이어갑니다.

---

# 4. 터치포인트 구조 자체는 유지

터치포인트 기준의 분류를 완전히 삭제하는 것은 아니다.

발표와 서비스 설명에서는 **경험 단계 중심**으로 보여주고,  
실제 기능 설계와 IA에서는 기존처럼 **터치포인트 중심**으로 관리한다.

## 발표

```text
준비
→ 해석
→ 체험
→ 기록 · 확장
```

## 상세 기능 / IA

```text
WEB
SMART GLASS
INTERACTIVE SCREEN
CUSTOM GOODS
```

### 정리

> **서비스 설명은 경험 중심으로, 상세 설계는 터치포인트 중심으로 정리한다.**

---

# 5. 시퀀스화

## 시퀀스란

시퀀스는 각각의 기능을 따로 보여주는 것이 아니라,

**한 명의 방문객이 처음부터 끝까지 어떤 순서로 궁온을 경험하는지를 하나의 이야기로 연결하는 것**이다.

기존 방식:

```text
WEB 기능
SMART GLASS 기능
INTERACTIVE SCREEN 기능
```

변경 방식:

```text
사용자의 행동
↓
다음 상황 발생
↓
다음 경험으로 이동
↓
다음 터치포인트 사용
↓
결과 생성
```

즉,

> 기능을 나열하는 것이 아니라 방문객의 실제 경험을 Story로 만든다.

# 6. GUNG:ON 전체 Experience Sequence

## 01. 방문 전

방문객은 웹에서 궁온이 어떤 서비스인지 확인하고, 현장에서 어떻게 이용하는지 미리 이해한다.

```text
WEB

서비스 이해
이용 방법 확인
```

↓

## 02. 경복궁 도착

현장에서 스마트 글라스를 대여하고 착용한 뒤 관람을 시작한다.

```text
SMART GLASS

장비 대여
장비 착용
관람 시작
```

↓

## 03. 페르소나 선택

스마트 글라스를 착용한 뒤  
방문객은 왕 / 왕비 / 세자 중 **이번 관람에서 경복궁을 바라볼 인물**을 선택한다.

페르소나는 단순한 캐릭터 선택이 아니라,  
이후 같은 공간을 어떤 관점에서 이해할지를 정하는 **관람의 기준**이 된다.

```text
SMART GLASS

페르소나 안내

↓

왕 / 왕비 / 세자 확인

↓

인물별 관람 관점 확인

↓

페르소나 선택

↓

선택한 인물 확인

↓

공간 관람 시작
```

---

### 03_1. 페르소나 안내

처음에는 페르소나 선택이 무엇을 의미하는지 짧게 설명한다.

```text
이번 관람에서
경복궁을 바라볼 인물을 선택해주세요.

선택한 인물에 따라
같은 공간도 서로 다른 관점으로 볼 수 있습니다.
```

사용자가 단순히 좋아하는 인물을 고르는 것이 아니라,

> **누구의 관점으로 경복궁을 경험할 것인지 선택하는 것**

임을 이해할 수 있게 한다.

---

### 03_2. 왕 / 왕비 / 세자 확인

세 인물을 한눈에 비교할 수 있도록 보여준다.

```text
왕

왕의 역할과 시선으로
궁궐의 주요 공간을 바라봅니다.


왕비

왕비의 생활과 역할을 중심으로
궁궐의 공간을 바라봅니다.


세자

세자의 배움과 생활을 중심으로
궁궐의 공간을 바라봅니다.
```

각 인물에 대한 설명은 길게 제공하지 않고  
**이 인물을 선택했을 때 무엇이 달라지는지** 중심으로 보여준다.

---

### 03_3. 인물별 관람 관점 확인

사용자는 선택하기 전에  
각 페르소나가 어떤 관점으로 공간을 보여주는지 간단히 확인할 수 있다.

```text
왕
국가의 일을 결정하고
궁궐을 운영했던 관점

왕비
왕실의 생활과
궁중 안의 역할을 중심으로 한 관점

세자
배우고 성장하며
왕이 되기 위해 준비했던 관점
```

이 단계의 목적은 인물의 전체 생애를 설명하는 것이 아니라,

> **이 페르소나를 선택하면 경복궁을 어떤 시선으로 보게 되는지**

알려주는 것이다.

---

### 03_4. 페르소나 선택

사용자는 자신이 원하는 인물을 하나 선택한다.

```text
왕

또는

왕비

또는

세자

↓

선택
```

선택한 페르소나는  
이후 스마트 글라스의 공간 해석에 반영된다.

```text
선택한 페르소나

+

현재 공간

↓

현재 공간에 맞는
인물 기반 해석 제공
```

예를 들어 같은 공간이라도  
선택한 인물에 따라 강조되는 내용과 관점이 달라질 수 있다.

---

### 03_5. 선택한 인물 확인

페르소나를 선택하면  
관람을 시작하기 전에 선택 결과를 한 번 확인한다.

```text
이번 관람의 인물

왕
```

또는

```text
이번 관람은
왕비의 시선으로 시작합니다.
```

이후 바로 실제 공간 관람으로 이어진다.

```text
페르소나 선택 완료

↓

실제 경복궁 관람 시작

↓

현재 전각 확인

↓

선택한 인물의 관점으로
공간 해석
```

---

### 03_6. 페르소나가 이후 경험에 미치는 영향

페르소나는 하나의 시작 화면에서 끝나는 선택이 아니다.

이후 공간을 이해하는 방식에 계속 반영된다.

```text
페르소나 선택

↓

현재 공간 확인

↓

페르소나와 공간의 관계 확인

↓

인물 기반 공간 해석

↓

실제 공간 바라보기
```

즉,

```text
페르소나
= 이번 관람의 관점
```

으로 사용한다.

---

### 03_7. 페르소나 선택 단계의 원칙

- 페르소나 선택은 현장에서 스마트 글라스를 착용한 뒤 진행한다.
- WEB에서는 페르소나를 미리 선택하지 않는다.
- 왕 / 왕비 / 세자 세 가지로 구성한다.
- 각 인물의 설명을 길게 제공하지 않는다.
- 인물의 전체 생애보다 관람 관점의 차이를 먼저 보여준다.
- 선택한 페르소나는 이후 공간 해석에 실제로 반영되어야 한다.
- 페르소나를 게임 캐릭터처럼 점수나 능력치로 표현하지 않는다.
- 특정 페르소나 선택에 따라 관람 가능한 공간을 제한하지 않는다.
- 페르소나는 역사적 사실을 바꾸는 장치가 아니라, 같은 공간을 바라보는 관점을 달리하는 장치로 사용한다.

---

### 03_8. 핵심

> **페르소나 선택은 왕 / 왕비 / 세자 중 한 명을 고르는 단계가 아니라, 이번 경복궁 관람을 어떤 인물의 관점으로 바라볼지 정하는 단계다.**

```text
인물을 선택한다

↓

관람의 관점이 정해진다

↓

같은 공간을
선택한 인물의 시선으로 이해한다
```

↓

## 04. 공간 관람

페르소나를 선택한 뒤,  
방문객은 스마트 글라스를 착용한 상태로 실제 경복궁을 이동하며 관람을 시작한다.

이 단계에서는 아직 많은 역사 정보를 보여주지 않는다.

먼저 사용자가 **지금 어떤 공간에 들어왔는지 확인하고, 실제 전각을 충분히 바라볼 수 있도록 하는 것**이 목적이다.

```text
실제 경복궁 이동

↓

현재 전각 인지

↓

전각 이름 확인

↓

실제 공간 바라보기

↓

공간 해석 시작
```

---

### 01. 현재 전각 인지

사용자가 새로운 공간에 들어오면  
스마트 글라스가 현재 관람 중인 전각을 인지한다.

```text
새로운 공간 진입

↓

현재 전각 인지

↓

해당 공간 확인

↓

공간에 맞는 관람 준비
```

이 단계에서 중요한 것은  
사용자의 이동 경로를 계속 추적하는 것이 아니라,

> **지금 보고 있는 공간이 어디인지 정확하게 확인하는 것**

이다.

### 제공 정보

- 현재 전각 이름
- 현재 공간 진입 여부
- 필요한 경우 최소한의 위치 안내

### 예시

```text
현재 전각

근정전
```

또는

```text
근정전에 도착했습니다.
```

정도로 간단하게 보여준다.

---

### 02. 실제 공간 먼저 바라보기

현재 전각을 확인한 뒤에는  
바로 많은 정보를 띄우기보다 사용자가 실제 공간을 먼저 바라볼 수 있도록 한다.

```text
현재 전각 확인

↓

실제 건축물과 공간 바라보기

↓

필요한 정보 제공
```

스마트 글라스는 실제 경복궁을 대신해서 보여주는 화면이 아니라  
사용자가 지금 보고 있는 공간을 이해하도록 돕는 역할을 한다.

따라서 이 단계에서는

- 긴 설명
- 많은 버튼
- 여러 정보 카드
- 과도한 그래픽

을 바로 보여주지 않는다.

### 역할

> **사용자가 먼저 실제 공간을 보고, 그다음 필요한 역사 정보를 확인할 수 있게 한다.**

---

### 03. 기본 관람 상태

전각 사이를 이동하거나  
새로운 정보가 필요하지 않은 순간에는 최소한의 화면만 유지한다.

```text
기본 관람 상태

현재 전각
+
필요한 최소 안내
```

### 기본 상태에서 보여줄 수 있는 정보

- 현재 전각 이름
- 필요한 경우 이동 방향
- 안전과 관련된 최소 안내

상세한 역사 정보는  
사용자가 새로운 공간에 들어오거나 공간 해석이 시작될 때 제공한다.

---

### 04. 새로운 공간에 들어왔을 때

사용자가 다른 전각으로 이동하면  
스마트 글라스는 새로운 공간을 확인하고 그 공간에 맞는 내용으로 전환한다.

```text
이전 공간 관람

↓

이동

↓

새로운 전각 진입

↓

현재 전각 확인

↓

새로운 공간 해석 시작
```

이렇게 공간이 바뀔 때마다  
다음 단계인

- 인물 기반 공간 해석
- 역사적 사건
- 핵심 지점

도 현재 전각에 맞게 달라진다.

---

### 04-1.공간 관람과 공간 해석의 차이

두 단계는 역할을 구분한다.

#### [1] 공간 관람

> **지금 어디를 보고 있는지 확인하는 단계**

```text
현재 전각 인지
↓
전각 이름 확인
↓
실제 공간 바라보기
```

### [2] 공간 해석

> **그 공간을 어떻게 이해할지 알려주는 단계**

```text
인물 기반 공간 해석
+
역사적 사건
+
핵심 지점
```

즉,

```text
공간 관람
어디에 있는가?

↓

공간 해석
이 공간을 어떻게 바라볼 것인가?
```

로 이어진다.

---

### 04-2.공간 관람 단계의 원칙

- 현재 전각을 먼저 확인한다.
- 이동 중에는 정보량을 최소화한다.
- 실제 경복궁을 가리는 표현을 사용하지 않는다.
- 공간에 들어오자마자 긴 설명을 보여주지 않는다.
- 현재 공간과 관계없는 정보는 제공하지 않는다.
- 사용자가 실제 공간을 충분히 바라본 뒤 다음 정보가 이어지도록 한다.
- GPS 전체 이동 경로나 실시간 이동 기록은 핵심 기능으로 사용하지 않는다.
- 공간을 인지하지 못한 경우 잘못된 역사 정보를 보여주지 않는다.

---

### 04-3.핵심

> **공간 관람은 정보를 보여주는 단계가 아니라, 사용자가 현재 보고 있는 전각을 확인하고 실제 공간에 집중할 수 있도록 만드는 단계다.**

이후 공간이 확인되면  
선택한 인물의 관점, 역사적 사건, 핵심 지점을 통해 본격적인 공간 해석이 시작된다.

↓

## 05. 공간 해석

현재 전각을 확인한 뒤,  
스마트 글라스는 **선택한 인물과 현재 공간에 맞는 내용을 세 가지 기준으로 나누어 보여준다.**

이 단계의 목적은 많은 역사 정보를 한꺼번에 보여주는 것이 아니라,

> **누구의 시선으로 이 공간을 볼지, 이곳에서 어떤 일이 있었는지, 실제로 무엇을 봐야 하는지**

를 이해하게 하는 것이다.

```text
현재 전각 확인

↓

1. 인물 기반 공간 해석
누구의 시선으로 볼 것인가

↓

2. 역사적 사건
이 공간에서 무슨 일이 있었는가

↓

3. 핵심 지점
실제 공간에서 무엇을 봐야 하는가

↓

실제 공간 다시 바라보기
```

---

### 05-1. 인물 기반 공간 해석

선택한 왕 / 왕비 / 세자와  
현재 보고 있는 공간의 관계를 중심으로 내용을 보여준다.

같은 공간이라도  
어떤 인물을 선택했는지에 따라 공간을 바라보는 관점이 달라진다.

```text
선택한 인물 확인

↓

현재 공간과 인물의 관계 확인

↓

인물의 입장에서 공간의 의미 설명

↓

실제 공간 바라보기
```

### 제공 정보

- 현재 선택한 인물
- 인물과 현재 공간의 관계
- 해당 인물에게 이 공간이 어떤 의미였는지
- 공간에서 주목해야 할 역할이나 상황

### 예시 구조

```text
현재 인물
왕

↓

이 공간은 왕에게 어떤 장소였는가?

↓

왕이 이 공간에서
어떤 역할을 했는지 짧게 설명

↓

실제 공간에서 관련 지점 확인
```

### 역할

> **사용자가 단순히 건물을 보는 것이 아니라, 선택한 인물의 입장에서 공간을 이해하도록 한다.**

---

### 05-2. 역사적 사건

현재 공간에서 실제로 있었던  
대표 역사적 사건을 보여준다.

인물 기반 해석이

> **“이 인물에게 이 공간은 어떤 의미인가?”**

를 보여준다면,

역사적 사건은

> **“이 공간에서는 실제로 어떤 일이 있었는가?”**

를 보여주는 역할을 한다.

```text
현재 공간 확인

↓

이 공간과 연결된 대표 사건 확인

↓

사건의 주요 장면

↓

당시 인물과 행동

↓

사건의 핵심 내용
```

### 제공 정보

- 현재 공간과 연결된 대표 사건
- 사건이 일어난 상황
- 당시 주요 인물
- 중요한 행동이나 장면
- 사건을 이해하는 데 필요한 핵심 내용

### 표현 방식

긴 설명문을 읽게 하기보다

```text
짧은 설명

+

주요 인물

+

대표 장면

+

핵심 내용
```

중심으로 보여준다.

### 역할

> **지금 보고 있는 공간과 과거에 실제로 있었던 일을 연결해 이해하도록 한다.**

---

### 05-3. 핵심 지점

스마트 글라스는  
현재 공간에서 사용자가 놓치기 쉬운 부분을 알려준다.

화면 안에서만 정보를 보는 것이 아니라  
사용자의 시선을 다시 실제 건축물과 공간으로 돌려주는 역할을 한다.

```text
공간 해석

↓

주목할 지점 안내

↓

실제 공간에서 위치 확인

↓

짧은 의미 확인

↓

다시 공간 관람
```

### 제공 정보

- 주목할 건축물이나 공간 지점
- 주요 오브젝트
- 해당 지점이 중요한 이유
- 필요한 경우 짧은 추가 설명

### 예시 구조

```text
여기를 바라보세요

↓

실제 공간의 특정 지점 강조

↓

왜 중요한지 짧게 설명

↓

사용자가 직접 확인
```

### 역할

> **설명을 읽는 데서 끝나지 않고, 사용자가 실제 경복궁에서 무엇을 봐야 하는지 알 수 있게 한다.**

---

### 05-4. 세 가지 정보의 차이

| 구분 | 핵심 질문 | 역할 |
|---|---|---|
| **인물 기반 공간 해석** | 누구의 시선으로 볼 것인가? | 선택한 인물의 관점으로 공간 이해 |
| **역사적 사건** | 이 공간에서 무슨 일이 있었는가? | 공간과 실제 역사 사건 연결 |
| **핵심 지점** | 무엇을 주목해서 볼 것인가? | 실제 공간에서 볼 지점 안내 |

---

### 05-5. 전체 경험 흐름

```text
실제 공간을 바라봄

↓

인물의 관점으로 공간을 이해

↓

이 공간에서 있었던 사건을 확인

↓

실제 공간의 핵심 지점을 직접 확인

↓

다시 실제 경복궁을 바라봄
```

---

### 공간 해석 단계의 원칙

- 세 가지 정보를 한 화면에 한꺼번에 모두 보여주지 않는다.
- 긴 역사 설명보다 핵심 내용을 먼저 보여준다.
- 인물 기반 해석과 역사적 사건을 같은 내용으로 반복하지 않는다.
- 역사적 사건은 전문가가 검수한 내용을 기준으로 한다.
- 핵심 지점은 실제 공간에서 사용자가 직접 확인할 수 있어야 한다.
- 화면보다 실제 경복궁을 바라보는 시간이 길어야 한다.
- 사용자가 원할 경우에만 추가 정보를 확인할 수 있게 한다.

#### 핵심

> **공간 해석은 정보를 많이 보여주는 단계가 아니라, 인물의 관점과 역사적 사건, 핵심 지점을 통해 실제 경복궁을 더 잘 바라보게 하는 단계다.**

↓

## 06. 체험 안내

체험 프로그램이 있는 공간에 도착하면  
스마트 글라스가 현재 공간과 연결된 프로그램을 안내한다.

단순히 프로그램 이름만 보여주는 것이 아니라,  
**현재 보고 있는 공간과 체험이 어떤 관계인지 짧게 설명하고, 사용자가 참여 여부를 선택할 수 있도록 한다.**

```text
현재 공간 확인

↓

이 공간과 프로그램의 관계 안내

↓

프로그램 이름

↓

무엇을 체험하는지 짧게 설명

↓

참여 여부 선택
```

### 06_2. 제공 정보

- 현재 공간
- 프로그램 이름
- 이 공간에서 해당 체험을 하는 이유
- 사용자가 직접 하게 될 행동
- 체험 공간 안내
- 참여 / 건너뛰기

#### 예시 01. 오늘의 수라상

```text
현재 공간
소주방

↓

이곳에서는 왕실의 음식을 준비했습니다.

↓

오늘의 수라상

↓

왕실 음식을 고르고,
직접 상차림을 완성해보세요.

↓

체험하기 / 관람 계속하기
```

#### 예시 02. 훈민정음 서재

```text
현재 공간
훈민정음과 관련된 체험 공간

↓

글을 만들고 기록했던 당시의 방식을
직접 경험할 수 있습니다.

↓

훈민정음 서재

↓

나의 말을 옛 한글로 바꾸고,
직접 글씨를 써보세요.

↓

체험하기 / 관람 계속하기
```

### 06_3.역할

이 단계의 목적은 새로운 역사 정보를 길게 설명하는 것이 아니다.

스마트 글라스에서 이해한 공간의 의미가  
인터랙티브 스크린의 직접 체험으로 자연스럽게 이어지도록 연결한다.

```text
공간을 이해함

↓

왜 이 체험을 하는지 이해함

↓

참여 여부 선택

↓

직접 체험
```

### 06_4.원칙

- 프로그램 참여는 선택 사항이다.
- 체험을 강제로 시작하지 않는다.
- 프로그램 설명은 짧게 제공한다.
- 현재 공간과 체험의 관계를 먼저 보여준다.
- 자세한 행동 과정은 인터랙티브 스크린에서 안내한다.
- 건너뛰기를 선택하면 바로 경복궁 관람을 계속할 수 있다.

↓

## 07. 직접 체험

체험 참여를 선택한 방문객은  
인터랙티브 스크린에서 **현재 공간의 역사적 의미와 연결된 행동을 직접 수행한다.**

이 단계의 목적은 설명을 한 번 더 보여주는 것이 아니라,  
스마트 글라스에서 보고 이해한 내용을 **선택 · 조작 · 쓰기 · 배치와 같은 행동으로 직접 경험하게 하는 것**이다.

```text
스마트 글라스에서 공간 이해

↓

체험 참여 선택

↓

인터랙티브 스크린으로 이동

↓

프로그램의 역사적 상황 확인

↓

직접 행동

↓

행동에 따른 피드백

↓

나의 체험 결과 생성
```

---

### 07_1. 체험 시작

인터랙티브 스크린에서는 먼저  
**지금 어떤 체험을 하게 되는지와 이 체험이 현재 공간과 어떤 관계가 있는지** 짧게 안내한다.

스마트 글라스에서 이미 공간의 역사적 내용을 확인했기 때문에  
같은 설명을 길게 반복하지 않는다.

### 제공 정보

- 프로그램 이름
- 현재 공간과 프로그램의 관계
- 사용자가 하게 될 행동
- 체험 시작 안내

#### 역할

> **스마트 글라스에서 이해한 내용을 직접 행동으로 자연스럽게 이어준다.**

---

### 07_2. 직접 행동

방문객은 프로그램에 따라  
단순히 내용을 읽는 것이 아니라 직접 선택하고 조작한다.

궁온의 체험은 다음과 같은 행동을 중심으로 구성한다.

```text
선택

+

조작

+

쓰기

+

배치
```

모든 프로그램에서 네 가지 행동을 모두 사용할 필요는 없으며,  
각 프로그램의 역사적 내용과 가장 잘 맞는 행동을 선택한다.

---

#### 오늘의 수라상

##### 체험 내용

왕실 음식과 수라 준비 과정을  
직접 선택하고 배치하며 경험한다.

```text
왕실 음식 확인

↓

음식 선택

↓

디지털 조리

↓

수라상 배치

↓

상차림 완성

↓

결과 확인
```

#### 주요 행동

- 음식 선택
- 조리 과정 조작
- 음식 위치 배치
- 수라상 완성

#### 체험 목적

> **왕실의 음식 문화를 설명으로만 보는 것이 아니라, 직접 수라상을 구성하며 경험한다.**

---

### 훈민정음 서재

#### 체험 내용

사용자가 자신의 말을 입력하고  
글씨를 직접 쓰는 과정을 통해 훈민정음과 글쓰기 문화를 경험한다.

```text
나의 문장 입력

↓

옛 한글 형태로 확인

↓

먹 갈기

↓

붓글씨 쓰기

↓

글씨 완성

↓

결과 확인
```

#### 주요 행동

- 문장 입력
- 글자 확인
- 먹 갈기 조작
- 붓글씨 쓰기
- 결과 완성

#### 체험 목적

> **훈민정음을 정보로 배우는 데서 끝나지 않고, 자신의 말을 직접 쓰는 과정으로 경험한다.**

---

### 07_3. 행동에 따른 피드백

사용자가 행동하면  
인터랙티브 스크린은 그 행동에 맞는 반응을 바로 보여준다.

예를 들어

```text
음식을 선택함
→ 수라상에 음식이 놓임

먹을 갈음
→ 먹의 상태가 변화함

글씨를 씀
→ 작성한 글씨가 화면에 남음
```

처럼

**행동 → 화면 반응 → 다음 행동**

이 자연스럽게 이어지도록 한다.

#### 역할

> **사용자가 자신의 행동이 체험에 실제로 반영되고 있다는 것을 알 수 있게 한다.**

---

#### 07_4. 나만의 결과 만들기

체험의 마지막에는  
사용자가 직접 선택하거나 작성한 내용을 바탕으로 개인의 결과가 만들어진다.

```text
사용자의 행동

↓

선택 · 쓰기 · 배치 결과 반영

↓

개인의 체험 결과 생성

↓

결과 확인
```

예:

#### 오늘의 수라상

- 선택한 음식
- 완성한 상차림

#### 훈민정음 서재

- 입력한 문장
- 직접 작성한 글씨

이 결과는 다음 단계에서  
웹의 관람 기록으로 이어진다.

---

#### 직접 체험 단계의 원칙

- 스마트 글라스에서 본 설명을 그대로 반복하지 않는다.
- 현재 공간의 역사적 의미와 관계있는 행동을 사용한다.
- 단순한 영상 시청만으로 체험을 끝내지 않는다.
- 단순 정답 맞히기 중심의 퀴즈로 구성하지 않는다.
- 사용자가 직접 선택 · 조작 · 쓰기 · 배치하도록 한다.
- 사용자의 행동에 따라 화면이 반응해야 한다.
- 사용자의 행동이 최종 결과에 반영되어야 한다.
- 프로그램 참여는 선택 사항이다.
- 체험 도중 나가더라도 전체 경복궁 관람은 계속할 수 있다.

---

#### 핵심

> **직접 체험은 스마트 글라스에서 이해한 공간의 의미를 실제 행동으로 옮기는 단계다.**

```text
공간을 본다

↓

공간을 이해한다

↓

직접 행동한다

↓

나의 결과를 만든다
```
↓

## 08. 체험 결과 확인

체험을 마치면  
방문객이 직접 선택하고 쓰고 배치한 내용이 하나의 **개인 체험 결과**로 정리된다.

이 단계에서는 단순히 “체험 완료”라고 알려주는 것이 아니라,

> **내가 무엇을 했고, 그 행동이 어떤 결과로 남았는지**

확인할 수 있도록 한다.

```text
체험 완료

↓

사용자의 행동 정리

↓

개인 결과 완성

↓

결과 확인

↓

관람 기록으로 저장
```

---

### 08_1. 체험 결과 완성

체험 과정에서 사용자가 했던 행동을 바탕으로  
각 프로그램마다 다른 형태의 결과가 만들어진다.

```text
선택
+
쓰기
+
배치
+
조작

↓

나만의 체험 결과
```

모든 사용자에게 같은 완료 화면을 보여주는 것이 아니라,  
**사용자가 실제로 한 행동이 결과에 반영되는 것**이 중요하다.

---

### [1] 오늘의 수라상

사용자가 선택하고 배치한 음식이  
하나의 완성된 수라상 결과로 정리된다.

```text
선택한 음식

+

음식 배치

↓

나의 수라상 완성
```

#### 결과에 포함되는 내용

- 선택한 음식
- 완성한 수라상 구성
- 체험한 프로그램 이름
- 완성된 상차림 이미지

#### 예시

```text
오늘의 수라상이 완성되었습니다.

내가 선택한 음식
○○
○○
○○

완성한 수라상
[결과 이미지]
```

---

### [2] 훈민정음 서재

사용자가 입력한 문장과 직접 작성한 글씨가  
하나의 개인 결과로 정리된다.

```text
입력한 문장

+

직접 작성한 글씨

↓

나의 글 완성
```

#### 결과에 포함되는 내용

- 사용자가 입력한 문장
- 변환된 글자
- 직접 작성한 글씨
- 완성된 결과 이미지

#### 예시

```text
나의 글이 완성되었습니다.

내가 남긴 문장
“……”

[직접 작성한 글씨]
```

---

### 08_2. 결과 확인

사용자는 체험이 끝난 직후  
자신이 만든 결과를 인터랙티브 스크린에서 확인한다.

```text
체험 완료

↓

완성된 결과 확인

↓

내가 한 행동과 결과 연결

↓

체험 종료
```

이 단계에서 너무 많은 설명을 추가하기보다  
**사용자가 만든 결과 자체가 중심에 보이도록 한다.**

#### 제공 정보

- 프로그램 이름
- 완성된 개인 결과
- 사용자가 선택하거나 작성한 내용
- 체험 완료 상태
- 웹에서 다시 확인할 수 있다는 안내

---

### 08_3. 웹 관람 기록으로 이어지기

완성된 결과는 체험이 끝난 뒤 사라지지 않고  
웹의 `나의 관람 기록`에서 다시 확인할 수 있도록 저장된다.

```text
인터랙티브 스크린

체험 결과 완성

↓

관람 기록 저장

↓

WEB

나의 관람 기록에서 다시 확인
```

이때 사용자가 스마트 글라스나 인터랙티브 스크린을  
웹과 직접 연결하거나 관리하게 만들지는 않는다.

서비스 안에서 같은 관람 경험의 결과가  
자연스럽게 이어지는 구조로 설계한다.

---

### 08_4. 직접 체험과 체험 결과의 차이

#### 07. 직접 체험

> **사용자가 무엇을 하는가**

```text
선택
쓰기
조작
배치
```

↓

#### 08. 체험 결과

> **그 행동으로 무엇이 남는가**

```text
완성된 수라상

또는

직접 작성한 글
```

즉,

```text
행동

↓

반응

↓

결과

↓

기록
```

으로 이어진다.

---

### 08_5. 체험 결과 단계의 원칙

- 사용자가 실제로 한 행동이 결과에 반영되어야 한다.
- 모든 사용자에게 동일한 결과를 보여주지 않는다.
- 단순한 `체험 완료` 화면으로 끝내지 않는다.
- 결과 화면에서는 사용자가 만든 내용을 중심으로 보여준다.
- 결과를 확인한 뒤 자연스럽게 현장 관람으로 돌아갈 수 있어야 한다.
- 완성된 결과는 이후 웹의 관람 기록에서 다시 확인할 수 있어야 한다.
- 체험을 중간에 종료한 경우 완료된 결과로 저장하지 않는다.
- 결과 확인을 위해 별도의 복잡한 저장 행동을 요구하지 않는다.

---

#### 핵심

> **체험 결과는 사용자의 행동이 일회성 체험으로 끝나지 않고, 개인의 기록으로 남는 단계다.**

```text
직접 행동한다

↓

나만의 결과가 완성된다

↓

결과를 확인한다

↓

관람 기록으로 이어진다
```

↓

## 09. 관람 기록

완료한 프로그램과 체험 결과는  
웹의 **나의 관람 기록**에 자동으로 저장된다.

이 단계의 목적은 체험을 단순히 완료하는 데서 끝내지 않고,  
현장에서 경험한 내용을 **관람 이후에도 다시 확인할 수 있는 개인 기록으로 이어주는 것**이다.

```text
체험 완료

↓

체험 결과 저장

↓

관람 기록에 연결

↓

WEB에서 다시 확인
```

---

### 09_1. 체험 결과 저장

인터랙티브 스크린에서 프로그램을 완료하면  
사용자가 만든 결과가 해당 관람의 기록으로 저장된다.

사용자가 별도로 저장 버튼을 누르거나  
스마트 글라스와 웹을 직접 연결할 필요는 없다.

```text
프로그램 완료

↓

개인 체험 결과 확정

↓

현재 관람 기록에 자동 저장
```

#### 저장되는 내용

- 완료한 프로그램
- 프로그램별 체험 결과
- 체험 완료 여부
- 선택한 페르소나
- 경험한 주요 공간

---

### 09_2. 나의 관람 기록

웹에서는 현장에서 경험한 내용을  
`나의 관람 기록`을 통해 한 번에 확인할 수 있다.

```text
나의 관람 기록

├─ 선택한 인물
├─ 경험한 주요 공간
├─ 완료한 프로그램
└─ 프로그램별 체험 결과
```

단순히 프로그램 완료 여부만 보여주는 것이 아니라,

> **오늘 누구의 시선으로 어떤 공간을 보고, 무엇을 직접 체험했는지**

한 번에 돌아볼 수 있도록 구성한다.

---

### 09_3. 프로그램별 결과 확인

완료한 프로그램을 선택하면  
해당 프로그램에서 만든 결과를 다시 확인할 수 있다.

```text
완료 프로그램 선택

↓

체험 결과 확인

↓

내가 선택하거나 작성한 내용 확인
```

#### [1] 오늘의 수라상

```text
오늘의 수라상

완성한 수라상
선택한 음식
상차림 결과
```

#### [2] 훈민정음 서재

```text
훈민정음 서재

내가 입력한 문장
직접 작성한 글씨
완성한 결과
```

---

### 09_4. 현장 경험과 기록 연결

웹의 기록은 현장과 별개의 새로운 콘텐츠가 아니라  
**현장에서 실제로 경험한 내용을 정리해서 다시 보여주는 역할**을 한다.

```text
SMART GLASS

공간을 보고 이해함

↓

INTERACTIVE SCREEN

직접 행동하고 결과를 만듦

↓

WEB

오늘의 경험을 기록으로 확인
```

즉,

```text
공간 경험

↓

직접 체험

↓

체험 결과

↓

관람 기록
```

으로 이어진다.

---

### 09_5. 관람 중에는 기록을 관리하지 않는다

현장 관람 중 사용자의 중심 행동은  
기록을 정리하는 것이 아니라 실제 경복궁을 관람하는 것이다.

따라서 웹의 기록은 사용자가 계속 관리해야 하는 기능이 아니라  
현장에서 만들어진 경험이 **자연스럽게 쌓이는 구조**로 설계한다.

```text
현장에서는

보고
이해하고
체험한다

↓

기록은 자동으로 남는다
```

필요한 경우 사용자는 관람 중에도 현재 진행 상태를 확인할 수 있지만,  
본격적으로 기록을 돌아보는 경험은 관람 이후에 이어진다.

---

### 09_6. 관람 기록에 포함되는 정보

| 구분        | 내용                           |
| --------- | ---------------------------- |
| 선택한 인물    | 왕 / 왕비 / 세자 중 이번 관람에서 선택한 인물 |
| 경험한 주요 공간 | 궁온 콘텐츠를 실제로 경험한 주요 전각        |
| 완료 프로그램   | 오늘의 수라상 / 훈민정음 서재            |
| 체험 결과     | 프로그램에서 사용자가 직접 만든 개인 결과      |
| 관람 상태     | 완료한 경험과 현재 진행 상태             |

---

### 09_7. 기록 단계의 원칙

- 사용자가 별도로 저장 행동을 반복하지 않도록 한다.
- 스마트 글라스와 웹을 사용자가 직접 연결하게 하지 않는다.
- 실제로 경험한 내용만 기록한다.
- 프로그램을 중간에 종료한 경우 완료 기록으로 남기지 않는다.
- 전체 이동 경로나 위치를 계속 기록하지 않는다.
- 관람 기록은 점수나 순위를 보여주는 기능으로 사용하지 않는다.
- 프로그램 참여 개수를 경쟁 요소로 만들지 않는다.
- 기록을 통해 현장에서 무엇을 경험했는지 쉽게 다시 확인할 수 있어야 한다.
- 이후 관람 후 경험과 커스텀 굿즈로 자연스럽게 이어질 수 있어야 한다.

---

### 09_8. 핵심

> **관람 기록은 현장에서 만든 경험을 자동으로 모아, 관람 이후에도 다시 돌아볼 수 있게 하는 단계다.**

```text
현장에서 경험한다

↓

결과가 남는다

↓

웹에 기록된다

↓

관람 이후 다시 확인한다
```
↓

## 10. 관람 이어가기

체험을 마친 방문객은 다시 실제 경복궁 관람으로 돌아가  
스마트 글라스와 함께 다음 공간을 둘러본다.

이 단계의 목적은 하나의 프로그램을 완료했다고 해서 경험이 끝나는 것이 아니라,  
**체험 결과를 남긴 뒤 다시 경복궁의 공간 관람으로 자연스럽게 이어지게 하는 것**이다.

```text
체험 완료

↓

결과 확인

↓

실제 공간으로 시선 전환

↓

다음 공간으로 이동

↓

새로운 전각 확인

↓

공간 관람 다시 시작
```

---

### 10_1. 체험에서 관람으로 돌아가기

인터랙티브 스크린에서 체험을 마치면  
사용자는 다시 실제 경복궁을 관람하는 흐름으로 돌아간다.

```text
INTERACTIVE SCREEN

체험 완료

↓

체험 결과 확인

↓

SMART GLASS

다음 관람 안내

↓

실제 경복궁 관람
```

체험이 끝났다고 해서  
추가 행동을 강제로 요구하거나 다음 프로그램으로 바로 이동시키지 않는다.

#### 역할

> **직접 체험이 전체 관람을 끊는 별도의 활동이 아니라, 경복궁을 이해하는 과정의 일부가 되도록 한다.**

---

### 10_2. 다음 공간으로 이동

사용자는 자신의 관람 속도와 동선에 따라  
다음에 보고 싶은 공간으로 이동한다.

궁온이 정해진 순서대로 전각을 이동하게 만드는 것이 아니라,  
사용자가 이동한 공간에 맞춰 새로운 경험이 시작된다.

```text
현재 공간 관람 완료

↓

사용자가 다음 공간으로 이동

↓

새로운 전각 진입

↓

현재 전각 확인

↓

해당 공간에 맞는 내용 제공
```

#### 제공 정보

이동 중에는 필요한 정보만 최소한으로 보여준다.

- 현재 전각
- 필요한 경우 이동 방향
- 새로운 공간 진입 안내
- 체험 프로그램이 있는 경우 도착 안내

---

### 10_3. 새로운 공간에서 다시 관람 시작

다른 전각에 도착하면  
앞에서 경험했던 공간 관람 흐름이 다시 시작된다.

```text
새로운 공간 도착

↓

현재 전각 확인

↓

실제 공간 바라보기

↓

인물 기반 공간 해석

↓

역사적 사건

↓

핵심 지점 확인
```

이후 체험 프로그램이 있는 공간이라면

```text
체험 안내

↓

[사용자 선택]

체험 참여
또는
관람 계속
```

으로 이어진다.

---

### 10_4. 관람 중 반복되는 기본 흐름

궁온의 현장 경험은 하나의 긴 순서로만 진행되는 것이 아니라  
경복궁을 이동하면서 다음 흐름이 반복된다.

```text
공간 이동

↓

현재 전각 확인

↓

공간 바라보기

↓

공간 이해하기

↓

[체험 프로그램이 있는 경우]

체험 안내

↓

[선택]

직접 체험

↓

체험 결과 확인

↓

다시 공간 관람
```

프로그램이 없는 공간에서는

```text
공간 바라보기

↓

공간 이해하기

↓

다음 공간으로 이동
```

으로 바로 이어진다.

---

### 10_5. 사용자가 관람 흐름을 선택

모든 전각을 반드시 경험하거나  
모든 프로그램에 참여할 필요는 없다.

사용자는

- 원하는 공간을 더 오래 관람하거나
- 다른 공간으로 바로 이동하거나
- 프로그램에 참여하거나
- 프로그램을 건너뛸 수 있다.

궁온은 사용자의 관람을 통제하는 서비스가 아니라  
**사용자가 선택한 공간을 더 잘 이해하도록 돕는 역할**을 한다.

---

### 10_6. 관람 이어가기 단계의 원칙

- 체험이 끝난 뒤 자연스럽게 실제 공간 관람으로 돌아가게 한다.
- 다음 프로그램 참여를 강요하지 않는다.
- 정해진 관람 순서를 강요하지 않는다.
- 모든 전각 방문을 완료 조건으로 만들지 않는다.
- 사용자가 원하는 속도로 이동할 수 있어야 한다.
- 이동 중에는 정보량을 최소화한다.
- 새로운 전각에 들어왔을 때 해당 공간에 맞는 내용으로 전환한다.
- 프로그램이 없는 공간에서도 정상적으로 관람 경험이 이어져야 한다.
- 스마트 글라스는 이동을 통제하기보다 현재 공간의 이해를 돕는다.

---

### 10_7. 핵심

> **관람 이어가기는 하나의 체험을 끝낸 뒤 다시 실제 경복궁으로 돌아가, 사용자의 선택에 따라 다음 공간 경험을 계속하는 단계다.**

```text
공간을 이해한다

↓

필요하면 직접 체험한다

↓

결과를 남긴다

↓

다시 실제 공간으로 돌아간다

↓

다음 공간을 경험한다
```

↓

## 11. 관람 종료

경복궁 관람을 마친 방문객은  
스마트 글라스를 반납하고 현장 경험을 마무리한다.

이 단계는 단순히 장비를 반납하는 과정이 아니라,  
**현장에서 진행된 경험이 끝나고 이후 웹의 관람 기록으로 넘어가는 전환 단계**다.

```text
관람 마무리

↓

스마트 글라스 반납

↓

현장 경험 종료

↓

관람 기록으로 이어짐
```

---

### 11_1. 관람 마무리

방문객이 관람을 끝내기로 하면  
스마트 글라스는 현재 진행 중인 경험을 정리하고 종료 상태로 전환한다.

```text
관람 종료 선택

↓

현재 체험 상태 확인

↓

관람 마무리 안내
```

진행 중인 프로그램이 있다면  
완료되지 않은 상태로 기록하고, 완료된 결과와 구분한다.

---

### 11_2. 스마트 글라스 반납

방문객은 지정된 장소에서  
스마트 글라스를 반납한다.

```text
반납 장소 이동

↓

스마트 글라스 반납

↓

반납 완료
```

사용자가 웹과 스마트 글라스의 연결을 직접 해제하거나  
별도의 복잡한 종료 절차를 거치지 않도록 한다.

---

### 11_3. 현장 경험 종료

스마트 글라스 반납이 완료되면  
궁온의 현장 경험도 종료된다.

```text
SMART GLASS

현장 관람 종료

↓

WEB

관람 기록 확인
```

현장에서 만들었던

- 선택한 인물
- 경험한 주요 공간
- 완료한 프로그램
- 체험 결과

는 이후 웹에서 다시 확인할 수 있다.

---

### 11_4. 관람 후 경험으로 전환

관람 종료는 서비스 전체의 끝이 아니라  
**현장 경험에서 관람 후 경험으로 넘어가는 지점**이다.

```text
현장

보고
이해하고
체험함

↓

관람 종료

↓

관람 이후

기록을 다시 확인하고
경험을 떠올림
```

이후 사용자는 웹의 `나의 관람 기록`을 통해  
오늘의 경험을 다시 확인할 수 있다.

원하는 경우에는  
체험 결과를 활용한 커스텀 굿즈로 경험을 더 이어갈 수 있다.

---

### 11_5.관람 종료 단계의 원칙

- 장비 반납 과정은 간단해야 한다.
- 웹과 스마트 글라스를 직접 연결 해제하게 하지 않는다.
- 완료된 경험과 미완료된 경험을 구분한다.
- 반납 이후에도 완료한 체험 결과는 사라지지 않는다.
- 관람 종료와 동시에 모든 서비스 경험이 끊기지 않도록 한다.
- 현장 경험에서 웹의 관람 기록으로 자연스럽게 이어지게 한다.
- 굿즈 구매를 관람 종료의 필수 과정으로 만들지 않는다.

---

### 11_6. 핵심

> **관람 종료는 스마트 글라스를 반납하며 현장 경험을 마무리하고, 이후 웹의 관람 기록으로 자연스럽게 이어지는 단계다.**

```text
관람 마무리

↓

스마트 글라스 반납

↓

현장 경험 종료

↓

관람 후 기록 확인
```

↓

## 12. 관람 이후

경복궁 관람이 끝난 뒤 방문객은  
WEB의 `나의 관람 기록`에서 오늘 현장에서 경험한 내용을 다시 확인한다.

이 단계의 목적은 단순히 완료한 프로그램을 나열하는 것이 아니라,

> **오늘 어떤 페르소나의 시선으로 경복궁을 바라봤고, 어떤 공간(전각)을 경험했으며, 무엇을 직접 체험했는지 다시 돌아볼 수 있게 하는 것**

이다.

현장에서 순간적으로 지나갔던 경험을  
관람 이후에는 하나의 개인 기록으로 정리해서 보여준다.

```text
현장 경험 종료

↓

WEB 접속

↓

오늘의 관람 기록 확인

↓

선택한 인물 확인

↓

경험한 주요 공간 돌아보기

↓

완료한 프로그램과 결과 확인

↓

오늘의 경험 다시 떠올리기
```

---

### 12_1. 오늘의 관람 한눈에 보기

`나의 관람 기록`에 들어오면  
오늘 경험한 내용을 먼저 전체적으로 확인할 수 있다.

```text
오늘의 관람

선택한 인물

+

경험한 주요 공간

+

완료한 프로그램

+

체험 결과
```

사용자가 여러 메뉴를 각각 찾아다니지 않아도  
이번 관람에서 무엇을 경험했는지 한 화면에서 이해할 수 있도록 한다.

### 제공 정보

- 관람 날짜
- 선택한 페르소나
- 경험한 주요 공간
- 완료한 프로그램
- 프로그램별 체험 결과

---

### 12_2. 선택한 인물 다시 확인하기

현장에서 선택했던  
왕 / 왕비 / 세자 중 어떤 인물의 시선으로 관람했는지 다시 보여준다.

```text
이번 관람의 인물

왕
또는
왕비
또는
세자
```

단순히 페르소나 이름만 남기는 것이 아니라,

> **오늘의 관람이 어떤 관점에서 이루어졌는지 다시 떠올릴 수 있는 기준**

으로 활용한다.

예를 들어

```text
오늘은 '왕'의 시선으로
경복궁을 바라봤습니다.
```

처럼 이번 관람의 성격을 다시 보여줄 수 있다.

---

### 12_3. 경험한 주요 공간 돌아보기

방문객이 스마트 글라스를 통해 실제로 내용을 경험한  
주요 공간을 다시 확인할 수 있다.

```text
경험한 주요 공간

근정전
경회루
○○전
…
```

여기서는 사용자의 전체 이동 경로나 GPS 동선을 기록하는 것이 아니라,

**실제로 궁온의 콘텐츠를 통해 경험한 주요 공간만 기록한다.**

공간을 선택하면  
현장에서 확인했던 핵심 내용을 짧게 다시 볼 수 있다.

```text
공간 선택

↓

전각 이름

↓

이 공간에서 경험한 핵심 내용

↓

선택한 인물과 공간의 관계
```

#### 역할

> **현장에서 봤던 공간과 그때 이해했던 내용을 다시 연결한다.**

---

### 12_4. 완료한 프로그램 다시 보기

현장에서 완료한 프로그램을 확인한다.

```text
완료한 프로그램

오늘의 수라상

훈민정음 서재
```

프로그램별로

- 어떤 체험을 했는지
- 사용자가 어떤 행동을 했는지
- 어떤 결과를 만들었는지

다시 확인할 수 있다.

---

### 12_5. 나의 체험 결과 다시 확인하기

프로그램을 선택하면  
현장에서 직접 만든 개인 결과를 다시 볼 수 있다.

#### [1] 오늘의 수라상

```text
오늘의 수라상

내가 선택한 음식

+

완성한 상차림

+

나의 수라상 결과
```

#### [2] 훈민정음 서재

```text
훈민정음 서재

내가 입력한 문장

+

직접 작성한 글씨

+

완성한 결과
```

체험 결과는 단순한 `완료 표시`가 아니라  
현장에서 사용자가 실제로 했던 행동을 다시 떠올릴 수 있는 기록으로 남긴다.

---

### 12_6. 공간과 체험을 함께 돌아보기

관람 기록에서는  
공간과 프로그램을 서로 떨어진 정보로 보여주지 않는다.

사용자가

> **어디에서 → 무엇을 이해했고 → 무엇을 직접 경험했는지**

연결해서 볼 수 있도록 한다.

```text
실제 공간

↓

스마트 글라스로 공간 이해

↓

공간과 연결된 프로그램 체험

↓

나의 체험 결과

↓

관람 기록
```

예를 들어

```text
공간

소주방

↓

이 공간에서 이해한 내용

왕실 음식과 수라 준비

↓

직접 체험

오늘의 수라상

↓

나의 결과

내가 완성한 수라상
```

처럼 현장의 경험 흐름을 다시 확인할 수 있다.

---

### 12_7. 현장에서 지나간 경험 다시 떠올리기

현장에서는 실제 공간을 보고 이동하고 체험하는 데 집중하기 때문에  
모든 내용을 오래 기억하기 어렵다.

관람 이후 WEB은  
현장에서 경험했던 내용을 다시 천천히 돌아볼 수 있는 역할을 한다.

```text
현장

보고
이동하고
체험함

↓

관람 이후

기록을 통해
다시 보고
다시 떠올림
```

즉 WEB은 새로운 역사 콘텐츠를 계속 추가하는 것이 아니라,  
**현장에서 이미 경험한 내용을 다시 연결해주는 역할**을 한다.

---

### 12_8. 다음 경험으로 이어지기

관람 기록을 확인한 뒤  
사용자가 원하는 경우 자신의 체험 결과를 활용한  
커스텀 굿즈 경험으로 이어질 수 있다.

```text
나의 관람 기록 확인

↓

나의 체험 결과 확인

↓

[선택]

커스텀 굿즈 확인
```

굿즈 구매를 원하지 않는 경우에도  
WEB의 관람 기록만으로 궁온의 경험은 정상적으로 마무리된다.

---

### 12_9. 관람 이후 WEB 구조

```text
나의 관람 기록

├─ 오늘의 관람
│  ├─ 관람 날짜
│  └─ 선택한 페르소나
│
├─ 경험한 주요 공간
│  ├─ 공간 이름
│  └─ 공간에서 경험한 핵심 내용
│
├─ 완료한 프로그램
│  ├─ 오늘의 수라상
│  └─ 훈민정음 서재
│
└─ 나의 체험 결과
   ├─ 완성한 수라상
   └─ 직접 작성한 글
```

---

### 12_10. 관람 이후 단계의 원칙

- 현장에서 실제로 경험한 내용을 중심으로 보여준다.
- 새로운 콘텐츠를 과도하게 추가하지 않는다.
- 선택한 인물, 공간, 프로그램, 결과가 서로 연결되어 보여야 한다.
- 사용자의 전체 이동 경로나 GPS 동선을 기록하지 않는다.
- 실제로 경험한 주요 공간만 기록한다.
- 완료하지 않은 프로그램은 완료된 결과처럼 보여주지 않는다.
- 사용자가 별도로 기록을 정리하거나 저장할 필요가 없도록 한다.
- 관람 기록은 점수나 성취도를 보여주는 기능으로 만들지 않는다.
- 굿즈 구매 여부와 관계없이 관람 기록은 확인할 수 있어야 한다.
- 현장에서 만들어진 경험을 다시 떠올리는 데 집중한다.

---

### 12_11. 관람 기록과 12. 관람 이후의 차이

```text
9. 관람 기록

현장에서 만들어진 경험이
WEB에 저장되는 단계

↓

12. 관람 이후

저장된 경험을 사용자가
다시 보고 돌아보는 단계
```

즉,

```text
09 = 기록이 남는다

12 = 남은 기록을 다시 본다
```

로 역할을 구분한다.

---

### 12_12. 핵심

> **관람 이후는 현장에서 지나간 경험을 WEB에서 다시 연결해, 오늘의 경복궁 관람을 하나의 개인 경험으로 돌아보는 단계다.**

```text
누구의 시선으로 봤는지

+

어떤 공간을 경험했는지

+

무엇을 직접 체험했는지

+

어떤 결과를 만들었는지

↓

오늘의 관람 경험을 다시 떠올림
```


## 13. 경험 확장

관람을 마친 뒤 원하는 방문객은  
현장에서 자신의 페르소나와 프로그램 체험 결과가 반영된  
**커스텀 굿즈를 확인하고 선택해 구매할 수 있다.**

이 단계의 목적은 단순히 기념품을 판매하는 것이 아니라,

> **현장에서 만든 개인의 경험을 자신만의 실물 결과로 남기는 것**

이다.

굿즈 구매는 궁온의 필수 과정이 아니며,  
원하는 사용자만 선택적으로 경험한다.

```text
현장 관람 경험

↓

개인의 체험 결과 완성

↓

커스텀 굿즈에 결과 적용

↓

현장에서 실물 미리보기

↓

굿즈 선택

↓

[선택]
현장 구매
```

---

### 13_1. 나의 경험이 굿즈로 이어짐

커스텀 굿즈는 일반적인 경복궁 기념품과 달리  
사용자가 이번 관람에서 직접 만든 경험을 바탕으로 구성된다.

```text
이번 관람의 페르소나

+

완료한 프로그램

+

나의 체험 결과

↓

개인화된 커스텀 굿즈
```

즉, 동일한 굿즈를 모든 방문객에게 제공하는 것이 아니라  
**이번 관람에서 사용자가 실제로 선택하고 만든 결과가 굿즈에 반영된다.**

---

### 13_2. 프로그램 결과 적용

각 프로그램의 결과에 따라  
굿즈에 적용되는 내용도 달라진다.

#### 오늘의 수라상

```text
내가 선택한 음식

+

완성한 수라상

↓

수라상 결과가 적용된
커스텀 굿즈
```

예를 들어

- 내가 완성한 수라상 이미지
- 선택한 음식
- 해당 관람의 페르소나
- 관람 날짜

등을 활용할 수 있다.

#### [1]훈민정음 서재

```text
내가 작성한 문장

+

직접 쓴 글씨

↓

글씨 결과가 적용된
커스텀 굿즈
```

예를 들어

- 직접 작성한 글씨
- 사용자가 남긴 문장
- 해당 관람의 페르소나
- 관람 날짜

등을 활용할 수 있다.

---

### 13_3. 현장에서 굿즈 확인

궁온의 커스텀 굿즈 경험은  
**현장 구매를 중심으로 구성한다.**

관람을 마친 사용자는 굿즈 공간에서  
자신의 결과가 적용된 상품을 직접 확인한다.

```text
굿즈 공간 도착

↓

나의 체험 결과 불러오기

↓

적용 가능한 굿즈 확인

↓

개인화 결과 미리보기

↓

실물 상품 확인
```

단순히 상품 목록을 보는 것이 아니라,

> **“오늘 내가 만든 결과가 이 굿즈에 어떻게 남는지”**

바로 확인할 수 있도록 한다.

---

### 13_4. 굿즈 선택

사용자는 원하는 상품이 있을 경우  
자신의 결과를 적용할 굿즈를 선택한다.

```text
굿즈 종류 선택

↓

개인화 결과 적용

↓

최종 모습 확인

↓

구매 여부 결정
```

#### 제공 정보

- 굿즈 종류
- 적용되는 개인화 내용
- 완성 예상 모습
- 가격
- 제작 또는 수령 방식
- 구매 여부 선택

---

### 13_5. 현장 구매

구매를 선택하면  
현장에서 바로 주문을 완료한다.

```text
굿즈 선택

↓

개인화 결과 최종 확인

↓

현장 결제

↓

제작 / 수령 안내
```

굿즈 구매를 원하지 않는 경우에는  
추가 절차 없이 관람을 마칠 수 있다.

```text
구매하지 않음

↓

관람 경험 정상 종료
```

---

### 13_6. WEB은 보조 구매 경로

WEB에서의 굿즈 구매는  
궁온의 주된 굿즈 경험이 아니다.

현장에서 구매하지 않았더라도  
관람 이후 다시 구매하고 싶은 사용자를 위한 **보조 경로**로 제공한다.

```text
관람 이후

↓

WEB 나의 관람 기록

↓

이전 체험 결과 확인

↓

굿즈 다시 보기

↓

[선택]
온라인 구매
```

즉,

```text
주요 경로

현장에서 결과 확인
→ 굿즈 미리보기
→ 현장 구매


보조 경로

관람 이후 WEB
→ 이전 결과 확인
→ 굿즈 다시 보기
→ 온라인 구매
```

로 구분한다.

온라인 구매 기능 자체가  
관람 경험을 다시 떠올리게 하는 핵심 기능은 아니다.

관람 이후의 리마인드는 별도로  
WEB의 관람 기록이나 이미 구매한 굿즈를 통해 이루어진다.

---

### 13_7. 일반 기념품과 궁온 굿즈의 차이

```text
일반 기념품

경복궁을 방문했다는 사실을 남김


궁온 커스텀 굿즈

경복궁에서
내가 어떤 인물의 시선으로 보고
무엇을 직접 체험했는지를 남김
```

따라서 커스텀 굿즈는 단순한 상품 판매보다  
**개인의 관람 결과를 실물로 남기는 경험 확장 수단**으로 본다.

---

### 13_8. 경험 확장 단계의 원칙

- 굿즈 구매는 필수가 아니다.
- 구매하지 않아도 궁온의 전체 경험은 완성된다.
- 일반 상품이 아니라 개인의 체험 결과가 반영되어야 한다.
- 사용자가 직접 만든 결과가 무엇인지 알아볼 수 있어야 한다.
- 현장에서 직접 보고 선택하는 구매 경험을 중심으로 한다.
- WEB 구매는 관람 이후의 보조 구매 경로로 사용한다.
- 굿즈를 얻기 위해 포인트나 스탬프를 모으게 하지 않는다.
- 프로그램 완료에 대한 무료 보상처럼 제공하지 않는다.
- 구매를 강요하거나 관람의 완료 조건으로 만들지 않는다.
- 굿즈 자체보다 현장에서 만든 경험이 중심이 되어야 한다.

---

### 13_9. 핵심

> **경험 확장은 현장에서 만든 개인의 체험 결과를 원하는 경우 실물 굿즈로 남기는 단계다.**

```text
현장에서 경험한다

↓

나만의 결과를 만든다

↓

결과를 굿즈에 적용한다

↓

현장에서 직접 확인한다

↓

원하는 경우 구매한다

↓

관람 이후에도 실물로 남는다
```
## 14. 일상 ( 리마인드 )

관람이 끝난 뒤에도  
방문객은 WEB의 관람 기록이나 현장에서 구매한 커스텀 굿즈를 통해  
경복궁에서 경험했던 공간과 체험을 다시 떠올릴 수 있다.

이 단계의 목적은 새로운 콘텐츠를 추가하는 것이 아니라,

> **현장에서 만든 경험이 관람이 끝난 뒤에도 기억으로 이어지게 하는 것**

이다.

```text
관람 종료

↓

관람 기록 또는 굿즈가 남음

↓

일상에서 다시 확인

↓

경복궁에서의 경험을 떠올림
```

---

### 14_1. WEB 기록을 통해 다시 떠올리기

관람 이후 WEB의 `나의 관람 기록`에서  
이번 관람의 내용을 다시 확인할 수 있다.

```text
WEB

선택한 페르소나

+

경험한 주요 공간

+

완료한 프로그램

+

체험 결과
```

사용자는 기록을 보며

- 누구의 시선으로 관람했는지
- 어떤 공간을 경험했는지
- 무엇을 직접 체험했는지
- 어떤 결과를 만들었는지

다시 떠올릴 수 있다.

### 역할

> **현장에서 지나간 경험을 다시 볼 수 있는 디지털 기록으로 남긴다.**

---

### 14_2. 굿즈를 통해 다시 떠올리기

현장에서 커스텀 굿즈를 구매한 경우에는  
일상에서 굿즈를 보고 사용하면서 당시의 체험을 다시 떠올릴 수 있다.

```text
현장에서 만든 체험 결과

↓

커스텀 굿즈로 남음

↓

일상에서 사용하거나 바라봄

↓

당시의 공간과 체험을 다시 떠올림
```

예를 들어

```text
훈민정음 서재

↓

내가 직접 작성한 글씨

↓

글씨가 적용된 굿즈

↓

일상에서 굿즈를 보며
당시 체험을 떠올림
```

또는

```text
오늘의 수라상

↓

내가 완성한 수라상

↓

결과가 적용된 굿즈

↓

경복궁에서의 체험을 다시 떠올림
```

---

### 14_3. 굿즈를 구매하지 않아도 경험은 이어짐

기억을 이어가는 방식이  
굿즈 구매에만 의존해서는 안 된다.

굿즈를 구매하지 않은 사용자도  
WEB의 관람 기록을 통해 현장 경험을 다시 확인할 수 있다.

```text
굿즈 구매 X

↓

WEB 관람 기록

↓

관람 경험 다시 확인
```

굿즈를 구매한 사용자는

```text
WEB 관람 기록

+

커스텀 굿즈

↓

디지털 기록과 실물 경험을 함께 남김
```

으로 경험이 확장된다.

---

### 14_4. 리마인드의 역할

궁온에서 리마인드는  
별도의 알림 기능 하나를 의미하지 않는다.

```text
현장에서 경험함

↓

기록이 남음

↓

실물 또는 WEB에서 다시 마주침

↓

당시 경험을 다시 떠올림
```

처럼

**현장의 경험이 관람 이후에도 다시 기억될 수 있도록 만드는 전체 구조**를 의미한다.

따라서 리마인드를

```text
알림 메시지
```

하나의 기능으로 보기보다

```text
관람 기록

+

체험 결과

+

커스텀 굿즈
```

가 함께 만드는 관람 후 경험으로 본다.

---

### 14_5. 기억 이어가기 단계의 원칙

- 새로운 체험을 억지로 추가하지 않는다.
- 현장에서 실제로 경험한 내용을 중심으로 한다.
- WEB 기록만으로도 경험을 다시 돌아볼 수 있어야 한다.
- 굿즈 구매 여부와 관계없이 전체 서비스 경험은 완성된다.
- 굿즈는 기억을 남기는 선택적 수단이다.
- 리마인드를 단순 알림 기능으로 한정하지 않는다.
- 현장의 경험과 관람 후 기록이 서로 연결되어야 한다.
- 사용자가 원할 때 다시 확인할 수 있도록 한다.

---

### 14_6. 핵심

> **기억 이어가기는 현장에서 만든 경험을 WEB의 기록과 커스텀 굿즈를 통해 관람 이후의 일상에서도 다시 떠올릴 수 있게 하는 단계다.**

```text
현장에서 경험한다

↓

기록과 결과가 남는다

↓

일상에서 다시 마주한다

↓

경복궁에서의 경험을 다시 떠올린다
```
---

# 7. 연결성

교수님 피드백에서 중요한 것은  
각 터치포인트를 따로 설명하는 것이 아니라

> **한 터치포인트에서 만들어진 경험이나 정보가 다음 터치포인트에서 어떻게 이어지는지 보여주는 것**

이다.

따라서 장표에서는 각 기기보다  
**기기와 기기 사이의 연결 구간**을 중요하게 보여준다.

---

# 8. 주요 연결 구조

### 연결되는 경험

- 이용 방법 확인
- 관람 방식 이해

### 핵심 문장

> 웹에서 이해한 서비스가 실제 경복궁 현장 경험으로 이어집니다.

### 화살표 문구

**이용 맥락을 가지고 현장으로**

---

# 9. SMART GLASS → INTERACTIVE SCREEN

### 연결되는 경험

**공간 이해 → 직접 행동**

SMART GLASS에서는

- 현재 공간
- 페르소나의 관점
- 역사적 사건
- Focus Point

를 통해 공간을 이해한다.

이후 INTERACTIVE SCREEN에서는  
그 공간과 연결된 행동을 직접 수행한다.

```text
↓

```

### 핵심 문장

> 보고 이해한 공간을 직접 행동하며 경험합니다.

**공간의 이해를 행동으로**

### 핵심 문장

> 현장에서 한 행동이 사라지지 않고 개인의 관람 기록으로 남습니다.

### 화살표 문구

**체험 결과를 기록으로**

- 완료한 프로그램

- GPS 이동 기록
- 실시간 위치 추적
- 전체 이동 동선 저장

을 핵심 기능으로 설정하지 않는다.

> 어디를 갔다 왔는지 모두 위치 로그로 기록

이라고 표현하지 않는다.

대신

> **어떤 공간과 프로그램을 경험했는지 관람 기록으로 남는다**

라고 표현한다.

# 15. 경험 확장

## 15-1. 경험 확장의 정의

> **경복궁 현장에서 만들어진 경험이 관람이 끝난 뒤에도 기록과 결과의 형태로 남아 다시 이어지는 것**

궁온의 핵심 경험은 현장에서 이루어지지만,  
사용자가 현장을 떠나는 순간 모든 경험이 사라지는 구조로 끝내지 않는다.

현장에서

- 어떤 인물의 시선으로 공간을 바라봤는지
- 어떤 공간을 경험했는지
- 어떤 프로그램에 참여했는지
- 어떤 행동을 했는지
- 어떤 결과를 만들었는지

가 하나의 개인 경험으로 남고,  
관람 이후에도 다시 확인하거나 실물로 남길 수 있도록 한다.

---

## 15-2. 이번 단계에서 확장하지 않는 것

이번 프로젝트의 확장은 다음과 같은 방향을 우선적으로 의미하지 않는다.

```text
기능 추가
X

새로운 디바이스 추가
X

다른 궁궐로 서비스 범위 확대
X

프로그램 수 확대
X
```

현재는 서비스의 범위를 넓히기보다

```text
현장에서 만들어진 경험

↓

경험이 기록으로 남음

↓

관람 이후 다시 확인

↓

필요한 경우 실물로 남김

↓

일상에서 경험을 다시 떠올림
```

처럼 **하나의 경험이 시간적으로 얼마나 오래 이어지는지**에 집중한다.

---

# 15-3. 무엇이 확장되는가

궁온에서 확장되는 것은 단순한 콘텐츠가 아니라  
**사용자가 현장에서 만든 개인의 관람 경험**이다.

확장되는 정보는 크게 네 가지로 본다.

```text
1. 관람의 관점
선택한 페르소나

2. 공간 경험
실제로 궁온 콘텐츠를 경험한 주요 공간

3. 체험 경험
완료한 프로그램과 사용자의 행동

4. 개인 결과
프로그램에서 직접 만든 결과
```

이 정보들이 현장에서 사라지지 않고  
이후 WEB 기록과 선택적인 커스텀 굿즈로 이어진다.

---

# 15-4. 확장되는 경험의 핵심 단위

## 01. 페르소나

```text
왕
왕비
세자
```

단순히 선택 기록만 남기는 것이 아니라

> **이번 관람을 어떤 관점으로 경험했는가**

를 보여주는 기준으로 남긴다.

---

## 02. 경험한 공간

사용자가 스마트 글라스를 통해 실제로 경험한 주요 공간을 남긴다.

```text
전각 이름

+

해당 공간에서 경험한 핵심 내용
```

전체 GPS 이동 경로를 저장하는 방식이 아니라  
실제로 궁온 콘텐츠를 경험한 주요 공간만 기록한다.

---

## 03. 완료한 프로그램

```text
오늘의 수라상

훈민정음 서재
```

어떤 프로그램을 완료했는지만 보여주는 것이 아니라

```text
어디에서

↓

무엇을 이해하고

↓

무엇을 직접 했는지
```

까지 공간 경험과 연결한다.

---

## 04. 개인 체험 결과

프로그램에서 사용자가 직접 만든 결과를 남긴다.

```text
오늘의 수라상

선택한 음식
+
완성한 상차림


훈민정음 서재

입력한 문장
+
직접 작성한 글씨
```

이 결과가 이후

```text
WEB의 관람 기록

또는

커스텀 굿즈
```

로 이어지는 핵심 정보가 된다.

---

# 15-5. 경험 확장의 목적

궁온에서 경험을 확장하는 목적은  
사용자를 서비스 안에 계속 머물게 만드는 것이 아니다.

핵심은

> **현장에서 이해하고 행동한 경험이 관람이 끝난 순간 사라지지 않게 하는 것**

이다.

따라서 경험 확장은 다음 세 가지 역할을 가진다.

---

## 역할 01. 현장 경험을 하나의 기록으로 정리

현장에서는 사용자가 계속 이동하며

```text
공간을 보고

↓

내용을 이해하고

↓

프로그램을 체험한다.
```

각 순간의 경험은 서로 떨어져 있을 수 있다.

WEB에서는 이를

```text
페르소나

+

공간

+

프로그램

+

체험 결과
```

로 연결해 하나의 관람 기록으로 정리한다.

---

## 역할 02. 개인의 행동을 결과로 남김

궁온의 프로그램은  
모든 사용자가 동일한 화면을 보는 것으로 끝나지 않는다.

사용자가 직접

```text
선택하고
쓰고
배치하고
조작한 내용
```

이 개인의 결과로 남는다.

따라서 관람 이후에도

> **내가 무엇을 했는지 확인할 수 있는 경험**

으로 이어진다.

---

## 역할 03. 경험을 다시 떠올릴 계기 제공

관람이 끝난 이후에는

```text
WEB의 관람 기록

또는

커스텀 굿즈
```

를 다시 마주하면서  
현장에서 경험했던 공간과 행동을 떠올릴 수 있다.

이것이 궁온에서 말하는  
`기억 이어가기`의 핵심이다.

---

# 15-6. 경험 확장의 기본 원칙

## 원칙 01. 현장에서 만든 경험만 확장한다

관람 이후 새로운 콘텐츠를 계속 추가하기보다  
현장에서 실제로 경험한 내용을 중심으로 한다.

```text
현장에 없던 새로운 경험 제공
X

현장에서 경험한 내용을 다시 연결
O
```

---

## 원칙 02. 현장 경험이 중심이다

궁온의 핵심은 실제 경복궁에서 이루어진다.

WEB이나 굿즈가 현장 경험보다 중심이 되어서는 안 된다.

```text
현장 경험

↓

기록과 굿즈는
현장 경험을 이어주는 역할
```

---

## 원칙 03. 사용자가 만든 결과를 남긴다

단순히

```text
프로그램 완료
```

라고 표시하는 것으로 끝내지 않고

```text
사용자가 어떤 선택을 했는지

+

어떤 결과를 만들었는지
```

가 남도록 한다.

---

## 원칙 04. 확장은 선택할 수 있다

모든 사용자가 굿즈를 구매하거나  
관람 이후에도 계속 서비스를 이용해야 하는 것은 아니다.

```text
WEB 기록 확인
선택

굿즈 구매
선택

온라인 재구매
선택
```

추가 행동을 하지 않아도  
현장 관람 자체로 궁온의 기본 경험은 완성된다.

---

## 원칙 05. 기록과 실물은 같은 경험에서 출발한다

WEB과 굿즈가 각각 별개의 서비스처럼 보이지 않도록 한다.

둘 모두

```text
같은 페르소나

+

같은 프로그램

+

같은 체험 결과
```

를 기반으로 이어져야 한다.

---

# 16. 경험 확장 구조

궁온의 경험 확장은  
하나의 직선 구조보다 **현장 경험 이후 두 방향으로 이어지는 구조**로 본다.

```text
SMART GLASS

인물의 관점으로
실제 공간을 보고 이해

↓

INTERACTIVE SCREEN

공간의 의미를
직접 행동으로 경험

↓

개인의 체험 결과 완성

↓

┌──────────────────────────────┐
│                              │
│                              │
▼                              ▼

WEB                         현장 CUSTOM GOODS
관람 기록                   선택적 실물 확장

│                              │
│                              │
▼                              ▼

관람 이후                    관람 이후
기록 다시 확인               일상에서 굿즈 사용

│                              │
└──────────────┬───────────────┘
               ↓

        기억 이어가기

경복궁에서의 공간과
체험을 다시 떠올림
```

즉,

> **WEB 기록은 모든 사용자가 경험을 이어갈 수 있는 기본 확장이고, 커스텀 굿즈는 원하는 사용자가 선택하는 실물 확장이다.**

---

# 16-1. 1단계 — 현장에서 공간을 이해한다

## SMART GLASS

스마트 글라스에서는  
사용자가 실제 경복궁 공간을 바라보며  
선택한 인물의 관점으로 공간을 이해한다.

```text
현재 공간 확인

↓

인물 기반 공간 해석

↓

역사적 사건

↓

핵심 지점

↓

실제 공간 다시 바라보기
```

### 이 단계에서 만들어지는 경험

- 선택한 페르소나
- 현재 경험한 공간
- 공간과 인물의 관계
- 공간에서 이해한 역사적 맥락

### 확장과의 관계

이 단계에서 만들어진 정보는  
나중에 WEB에서

```text
누구의 시선으로

+

어떤 공간을 경험했는지
```

를 다시 확인하는 기록의 기준이 된다.

---

# 16-2. 2단계 — 이해한 내용을 직접 행동한다

## INTERACTIVE SCREEN

스마트 글라스에서 이해한 공간의 의미를  
인터랙티브 스크린에서 직접 행동으로 경험한다.

```text
공간 이해

↓

프로그램 안내

↓

체험 참여

↓

선택 · 조작 · 쓰기 · 배치

↓

개인 결과 완성
```

### 이 단계에서 만들어지는 경험

```text
오늘의 수라상

선택한 음식
완성한 상차림
```

또는

```text
훈민정음 서재

입력한 문장
직접 작성한 글씨
```

### 확장과의 관계

이 단계부터 궁온의 경험은  
단순한 역사 정보에서 **개인의 결과**로 바뀐다.

이 결과가 이후

```text
WEB 기록

+

커스텀 굿즈
```

로 이어진다.

---

# 16-3. 3단계 — 경험을 개인 기록으로 남긴다

## WEB

현장에서 만들어진 경험은  
WEB의 `나의 관람 기록`에 정리된다.

```text
선택한 페르소나

+

경험한 주요 공간

+

완료한 프로그램

+

개인의 체험 결과

↓

나의 관람 기록
```

사용자가 현장에서 직접 기록을 정리하거나  
매번 저장 버튼을 누를 필요는 없다.

현장에서 경험한 내용이  
하나의 관람 기록으로 자연스럽게 쌓이는 구조로 한다.

### WEB의 역할

WEB은 현장에서 했던 경험을 반복 제공하는 것이 아니라

> **서로 떨어져 있던 현장 경험을 하나의 개인 관람 기록으로 묶어주는 역할**

을 한다.

---

# 16-4. 4단계 — 현장에서 실물로 확장한다

## CUSTOM GOODS

커스텀 굿즈는  
WEB 다음에 반드시 거치는 단계가 아니다.

원하는 방문객만 선택하는  
**별도의 실물 확장 경로**다.

관람을 마친 사용자는 현장의 굿즈 공간에서  
자신이 만든 체험 결과가 적용된 상품을 확인할 수 있다.

```text
체험 결과 완성

↓

현장 굿즈 공간

↓

나의 결과 확인

↓

굿즈 적용 모습 확인

↓

[선택]

구매
또는
구매하지 않음
```

### 굿즈에 활용되는 정보

```text
선택한 페르소나

+

프로그램 종류

+

개인 체험 결과

+

필요한 경우 관람 날짜
```

### 예시

```text
훈민정음 서재

↓

내가 직접 작성한 글씨

↓

글씨가 적용된 커스텀 굿즈
```

또는

```text
오늘의 수라상

↓

내가 완성한 수라상

↓

수라상 결과가 적용된 커스텀 굿즈
```

### 굿즈의 역할

> **현장에서 만든 디지털 결과를 일상에서 사용할 수 있는 실물로 바꾸는 것**

이다.

단순한 방문 기념품과는 역할이 다르다.

---

# 16-5. 5단계 — 관람 이후 기록을 다시 본다

## 관람 이후 WEB

경복궁을 떠난 뒤에도  
사용자는 WEB에서 오늘의 관람 기록을 다시 확인할 수 있다.

```text
관람 종료

↓

WEB

↓

나의 관람 기록

↓

페르소나 확인

↓

경험한 공간 확인

↓

완료한 프로그램 확인

↓

체험 결과 다시 보기
```

### 이 단계의 핵심

현장에서 사용자는

```text
이동하고
보고
체험하는 것
```

에 집중한다.

관람 이후에는

```text
무엇을 봤는지

왜 그 공간을 그렇게 이해했는지

무엇을 직접 했는지

어떤 결과를 만들었는지
```

를 천천히 다시 돌아볼 수 있다.

---

# 16-6. 6단계 — 일상에서 기억이 이어진다

## 기억 이어가기

경험 확장의 마지막은  
새로운 서비스 기능이 아니다.

사용자가 일상에서

```text
WEB의 기록을 다시 보거나

또는

구매한 굿즈를 다시 마주하면서
```

경복궁에서의 경험을 떠올리는 상태다.

---

## WEB을 통한 기억 이어가기

```text
나의 관람 기록

↓

선택한 페르소나

↓

경험한 공간

↓

프로그램 결과

↓

현장 경험 다시 떠올리기
```

---

## 굿즈를 통한 기억 이어가기

```text
현장에서 만든 결과

↓

개인화 굿즈

↓

일상에서 사용

↓

결과를 다시 마주침

↓

당시의 공간과 체험을 떠올림
```

---

# 16-7. 굿즈 구매 여부에 따른 경험 차이

## 굿즈를 구매하지 않은 사용자

```text
현장 경험

↓

WEB 관람 기록

↓

관람 이후 다시 확인

↓

경험 다시 떠올리기
```

궁온의 전체 경험은 여기서 정상적으로 완성된다.

---

## 굿즈를 구매한 사용자

```text
현장 경험

↓

WEB 관람 기록

+

커스텀 굿즈

↓

디지털 기록과 실물이 함께 남음

↓

일상에서 경험 다시 떠올리기
```

굿즈 구매자는 기억을 이어갈 수 있는  
실물 접점을 하나 더 가지게 되는 것이다.

---

# 16-8. 온라인 굿즈 구매의 위치

온라인 굿즈 구매가 포함되더라도  
이를 궁온의 핵심 확장 경험으로 보지는 않는다.

주된 굿즈 경험은

```text
현장에서

나의 결과 확인

↓

굿즈 적용 모습 확인

↓

실물 확인

↓

선택 구매
```

이다.

온라인 구매는 관람 이후

```text
예전에 만든 체험 결과 확인

↓

굿즈를 다시 보고 싶음

↓

WEB에서 선택 구매
```

할 수 있는 **보조 구매 경로**다.

따라서 온라인 구매 기능 자체를  
`기억 이어가기` 기능으로 설명하지 않는다.


# 16-12. 확장성을 판단하는 기준

궁온의 새로운 기능이나 결과물을 추가할 때는  
다음 질문으로 경험 확장에 필요한지 판단한다.

### 01.

> 이 기능은 현장에서 만들어진 경험과 연결되어 있는가?

### 02.

> 사용자가 현장에서 만든 정보나 결과가 이후 단계까지 이어지는가?

### 03.

> 관람 이후에도 현장의 경험을 다시 떠올릴 수 있게 하는가?

### 04.

> 새로운 기능 자체가 중심이 아니라 현장 경험을 이어주는 역할을 하는가?

### 05.

> 사용자가 원하지 않아도 강제로 참여해야 하는 구조는 아닌가?

### 06.

> WEB, 스마트 글라스, 인터랙티브 스크린, 굿즈가 각각 따로 노는 것이 아니라 하나의 경험으로 연결되는가?

이 기준을 만족하지 않는 기능은  
단순한 기능 확장으로 보고 현재 궁온의 핵심 범위에서는 제외한다.

---

# 16-13. 경험 확장의 핵심 정의

> **궁온의 확장성은 새로운 기능을 계속 추가하는 것이 아니라, 현장에서 보고 이해하고 직접 행동한 경험이 개인의 기록과 결과로 남아 관람 이후의 일상까지 이어지도록 만드는 것이다.**

최종 구조는 다음과 같다.

```text
현장

SMART GLASS
공간을 이해

↓

INTERACTIVE SCREEN
직접 행동

↓

개인 체험 결과


          ↙                 ↘

WEB                         CUSTOM GOODS
기록으로 남김               실물로 남김
기본 경험                    선택 경험

          ↘                 ↙

            관람 이후

        경험을 다시 확인

               ↓

              일상

        경험을 다시 떠올림
```

# 17. 각각의 경험에서 무엇이 남는가

## SMART GLASS

현장에서

- 선택한 페르소나
- 경험한 공간
- 관람의 맥락

이 남는다.

---

## INTERACTIVE SCREEN

직접 수행한

- 프로그램 완료 상태
- 선택 결과
- 글씨 결과
- 배치 결과
- 개인 체험 결과

가 남는다.

---

## WEB

현장에서 만들어진 경험을 모아

- 방문 기록
- 선택한 페르소나
- 경험한 공간
- 완료 프로그램
- 프로그램별 체험 결과

를 하나의 관람 기록으로 보여준다.

---

## CUSTOM GOODS

WEB에 남은

- 페르소나
- 프로그램 결과
- 개인화된 체험 결과

를 실물 형태로 확장한다.

---

# 18. 리마인드

리마인드는 별도의 기능 하나를 의미하지 않는다.

궁온에서 리마인드는

> **현장에서 경험한 내용을 관람 이후 다시 떠올릴 수 있도록 연결하는 전체 구조**

다.

---

## WEB Reminder

관람 이후 WEB에서

- 나의 관람 기록
- 완료 프로그램
- 프로그램 결과

를 다시 확인할 수 있다.

### 역할

> 흩어진 현장 경험을 하나의 기록으로 다시 보여줍니다.

---

## Experience Result Reminder

오늘의 수라상과 훈민정음 서재에서  
직접 만든 결과를 다시 확인할 수 있다.

### 역할

> 직접 행동했던 순간을 개인의 결과를 통해 다시 떠올립니다.

---

## Custom Goods Reminder

Custom Goods는 무료 보상이나 체험 완료 보상이 아니다.

사용자가 원할 경우 자신의 경험을 일상에서 다시 떠올릴 수 있도록 하는  
**선택형 리마인드 매체**다.

```text
체험 결과

↓

WEB Preview

↓

선택 구매

↓

개인화된 실물

↓

일상에서 경험 리마인드
```

---

# 19. Custom Goods 최종 원칙

- 무료 굿즈가 아니다.
- 엽전 교환 방식이 아니다.
- Digital Stamp 교환 방식이 아니다.
- 구매는 선택 사항이다.
- Persona와 Program Result를 개인화에 활용한다.
- 서비스 이용을 위해 반드시 구매해야 하는 상품이 아니다.
- 관람 이후 경험을 일상으로 이어주는 역할을 한다.

---

# 20. 검증

이번 주차에는  
현재 솔루션이 실제 경복궁 관람에서 발견한 문제와 제대로 연결되는지 검증한다.

검증 구조:

```text
실제 관람에서 발견한 문제

↓

현재 솔루션

↓

문제와 해결안의 대응 관계 확인
```

즉,

> **실제 관람 인사이트 ↔ 현재 솔루션**

을 교차 검증한다.

---

# 21. 검증 장표

| 실제 관람에서 확인한 점 | 현재 솔루션 | 대응 |
|---|---|---|
| 무엇을 중심으로 봐야 하는지 알기 어려움 | Persona-based Interpretation + Focus Point | 대응 |
| 공간에서 일어난 역사적 사건을 현장에서 연결하기 어려움 | Historical Event | 대응 |
| 읽고 듣는 방식이 중심이라 직접 체험이 부족함 | Interactive Screen Program | 대응 |
| 현장에서 경험한 내용이 각각 따로 끝남 | WEB 관람 기록 | 대응 |
| 관람 이후 경험이 쉽게 끊김 | WEB Record + Custom Goods + Reminder | 대응 |

---

# 22. 검증 장표의 목적

검증 장표는

> 우리가 만든 솔루션이 좋다는 것을 주장하는 장표

가 아니다.

다음 관계를 보여주는 장표다.

```text
실제 경험에서 발견한 문제

↓

그 문제에 대응하는 서비스 경험

↓

전체 서비스 안에서 해결안이 수행하는 역할
```

```text
체험 결과를 기록으로

↓

기록을 개인화된 실물로

↓

현장의 경험을 일상으로
```

### 핵심 메시지

> 하나의 터치포인트에서 만들어진 경험이 다음 경험으로 자연스럽게 이어집니다.

---

## 04. EXPERIENCE EXTENSION

### 내용

```text
현장 경험

↓

관람 기록

↓

체험 결과 다시 보기

↓

Custom Goods

↓

일상 Reminder
```

### 핵심 메시지

> 현장에서 보고 행동한 경험을 기록하고, 관람 이후 일상까지 이어갑니다.

---

## 05. VALIDATION

### 내용

```text
실제 관람 Insight
↔
현재 Solution
```

### 핵심 메시지

> 실제 관람에서 발견한 문제와 현재 솔루션의 대응 관계를 다시 확인합니다.

# 24. 기존 장표에서 수정할 부분

기존에 서비스 구조를

```text
WEB

SMART GLASS

INTERACTIVE SCREEN
```

세 개의 큰 영역으로 나눈 장표는  
메인 분류 방식을 변경한다.

### 변경

```text
준비

↓

해석

↓

체험

↓

기록 · 확장
```

각 경험 단계 아래에  
해당 단계에서 사용하는 터치포인트를 배치한다.

즉,

**터치포인트가 서비스 구조의 제목이 아니라  
사용자의 경험을 지원하는 수단으로 보이게 변경한다.**

# 25. 문장 표현 수정

교수님 피드백에 따라  
현재 장표에서 문장이 어색하거나 연결이 부자연스러운 부분을 전체적으로 수정한다.

## 문장 수정 기준

- 한 문장에 하나의 의미만 담는다.
- 문장을 필요 이상으로 길게 쓰지 않는다.
- 주어와 목적어를 명확하게 한다.
- 비슷한 말을 반복하지 않는다.
- 기능 이름만 나열하지 않는다.
- 사용자가 실제로 무엇을 하는지를 중심으로 쓴다.
- 불필요한 영어 표현을 줄인다.
- 지나치게 거창한 표현을 사용하지 않는다.
- 서로 다른 장표에서 동일한 메시지를 반복하지 않는다.

> **시선을 켜다**

라는 표현은 교수님 피드백에 따라 다시 검토한다.

## 수정 방향

- `시선을 켜다`라는 표현이 자연스러운지 재검토
- Brand Essence인 `Perspective / 시선`은 유지 가능

- 의미가 바로 이해될 수 있도록 작성
- 지나치게 광고 문구처럼 만들지 않음
- 과도하게 추상적인 표현 지양

# 40. 3주차 최종 정리

## 서비스 구조

터치포인트 중심에서  
**경험 단계 중심으로 변경한다.**

```text
준비
→ 해석
→ 체험
→ 기록 · 확장
```

## 시퀀스

각 기능을 분리하지 않고  
**한 명의 방문객이 경험하는 하나의 Story로 연결한다.**

## 연결성

각 터치포인트가 무엇을 하는지가 아니라

> **한 터치포인트의 경험과 정보가 다음 터치포인트에서 어떻게 이어지는지**

보여준다.

## 확장성

현장에서 만든 경험을

```text
WEB 기록

↓

체험 결과 다시 보기

↓

Custom Goods

↓

일상 Reminder
```

로 확장한다.

## 검증

실제 경복궁 관람에서 발견한 문제와  
현재 Solution을 교차 검증한다.

## 브랜딩

이번 주부터 Visual Identity를 구체화한다.

```text
Logo

+

Slogan 수정

+

Typography 확정
```

# 41. 3주차 한 줄 요약

> **궁온의 3주차는 기능을 기기별로 나열하는 구조에서 벗어나, 준비–해석–체험–기록·확장으로 이어지는 하나의 관람 경험을 만들고, 그 경험이 터치포인트 사이에서 연결되어 관람 이후 일상까지 이어지는 구조를 구체화하는 단계다.**
