# 0. VER 2.0 변경 내용

VER 2.0에서는 기존의 터치포인트별 구조를 유지하면서,
사용자의 전체 관람 경험을 함께 볼 수 있도록 **경험 단계 기준을 추가한다.**

두 분류는 서로 대체하는 관계가 아니다.

```text
터치포인트 기준
=
어디에서 무엇을 제공하는가?

+

경험 단계 기준
=
사용자가 어떤 과정을 경험하는가?
```

### 터치포인트 기준

```text
웹
→ 안내 · 현황 · 기록

스마트 글라스
→ 페르소나 선택 · 공간 관람 · 공간 해석

인터랙티브 스크린
→ 직접 행동 · 체험 · 결과

커스텀 굿즈
→ 개인 체험 결과의 선택적 실물 확장
```

### 경험 단계 기준

```text
준비
→ 관람 방식을 이해하고 준비하다

시선
→ 페르소나의 관점으로 공간을 이해하다

체험
→ 공간의 의미를 행동으로 경험하다

기억
→ 경험을 남기고 다시 떠올리다
```

### 이번 버전에서 변경·추가된 핵심

1. 터치포인트 기준과 경험 단계 기준을 함께 사용
2. 경험 단계를 `준비 → 시선 → 체험 → 기억`으로 정리
3. `페르소나별 공간 해석`을 `페르소나별 공간 해석`으로 통일
4. 대표 프로그램을 `오늘의 수라상`, `훈민정음 서재` 두 개로 축소
5. 오늘의 수라상은 **소주방**, 훈민정음 서재는 **비현각**과 연결
6. 현장에서 만든 체험 결과가 웹 기록과 커스텀 굿즈로 나뉘어 이어지는 구조로 수정
7. 커스텀 굿즈는 **현장 구매 중심**, 웹 구매는 보조 경로로 정리
8. 브랜드 핵심을 `시선`, 대표 문구를 `시선을 따라, 궁을 만나다.`로 정리
9. 발표 장표 구성은 서비스 기획 통합본에서 제외
# 1. 프로젝트 정의

궁온은 관람객이 하나의 **페르소나**를 선택하고,
실제 경복궁을 그 페르소나의 관점으로 바라보며,
공간과 연결된 대표 프로그램을 직접 체험하는 관람 시스템이다.

궁온의 목적은 역사 정보를 더 많이 보여주는 것이 아니다.

**어떤 페르소나의 관점으로 공간을 볼 것인지 정하고,
그 공간에서 실제로 어떤 일이 있었는지 이해하며,
공간의 기능과 연결된 행동을 직접 경험하고,
그 경험을 관람 이후에도 다시 확인할 수 있게 하는 것**

을 핵심으로 한다.
# 2. 프로젝트 목표

## 기존 관람

```text
설명판
→ 오디오
→ 도슨트
→ QR
→ 사진 촬영
```

정보를 읽고 듣는 방식이 중심이었다.

## 궁온

```text
서비스 이해
→ 페르소나 선택
→ 공간 해석
→ 역사적 사건 이해
→ 직접 체험
→ 결과 기록
→ 관람 후 다시 보기
```

### 핵심 전환

> **역사를 보는 관람에서, 역사 속 페르소나의 시선으로 공간을 이해하고 행동으로 경험하는 관람으로 전환한다.**

---

# 3. 문제 정의

현재 경복궁에는 설명판, 오디오, 도슨트, QR 등  
여러 역사 정보 채널이 이미 있다.

문제는 정보 자체가 부족한 것이 아니라,

**실제 공간을 어떤 관점으로 바라봐야 하는지,  
무엇을 중심으로 봐야 하는지,  
그리고 공간의 의미를 어떻게 직접 경험할 수 있는지에 대한 구조가 부족하다는 점**

이다.

---

## 3.1 관람의 관점 부족

사용자는 역사 정보가 없어서가 아니라  
어떤 시선으로 공간을 바라봐야 하는지 기준이 부족하다.

### 주요 문제

- 설명이 사실 나열에 가까움
- 무엇을 중심으로 봐야 하는지 알기 어려움
- 공간마다 중요한 지점을 판단하기 어려움
- 같은 공간을 다른 인물의 입장에서 보는 경험이 부족함

---

## 3.2 수동적인 이해

읽고 듣는 정보는 많지만  
사용자가 직접 경험했다는 느낌은 부족하다.

### 주요 문제

- 행동을 통한 역사 체험 부족
- 사진만 찍고 지나가기 쉬움
- 다른 관람객의 흐름을 따라가기 쉬움
- 공간이 실제로 어떤 기능을 했는지 체감하기 어려움

---

## 3.3 경험의 연속성 부족

각 공간에서 경험한 내용이 따로 남아  
하나의 관람 경험으로 이어지기 어렵다.

### 주요 문제

- 어떤 공간에서 무엇을 했는지 기억이 흩어짐
- 완료한 체험을 한눈에 보기 어려움
- 프로그램 결과를 다시 보기 어려움
- 관람 이후 경험을 이어갈 구조가 부족함

---

# 4. 핵심 질문

> **관람객이 역사 속 인물의 관점으로 실제 경복궁을 바라보고, 공간에서 일어난 사건을 이해하며, 공간과 연결된 행동을 직접 경험한 뒤 그 결과를 하나의 관람 기록으로 이어가게 할 수 있을까?**

- 새로운 디지털 체험에 거부감이 적음

### 핵심 요구

> **새로운 시선으로 공간을 바라보고, 직접 경험하며 이해하고 싶다.**

---

## 보조 사용자

**경복궁을 기존과 다른 방식으로 다시 경험하고 싶은 재방문 관람객**

- 인공지능 동선 추천
- 맞춤 해설

- 인공지능 아카이브

## 최종 방향

궁온은 기능과 프로그램의 수를 늘리기보다
각 터치포인트가 담당하는 역할과 핵심 경험을 명확하게 남긴다.

### 웹

**안내 · 현황 · 기록**

### 스마트 글라스

**페르소나 선택 · 공간 관람 · 공간 해석**

### 인터랙티브 스크린

**직접 행동 · 체험 · 결과**

### 커스텀 굿즈

**개인 체험 결과의 선택적 실물 확장**

---

## 대표 프로그램 축소

초기에는 여러 전각에 다양한 프로그램을 배치하는 구조를 검토했지만,
프로그램 수가 많아질수록 화면, 체험 장치, 판넬, 프로토타입 등
제작 범위도 함께 커졌다.

따라서 교수 피드백을 반영해
궁온의 핵심 경험을 가장 잘 보여줄 수 있는 대표 프로그램 두 개만 남긴다.

```text
오늘의 수라상
→ 소주방

훈민정음 서재
→ 비현각
```

두 프로그램 모두

```text
공간 이해
→ 직접 행동
→ 개인 결과
```

라는 궁온의 핵심 경험을 보여주는 데 집중한다.
# 7. 경험 구조

궁온은 터치포인트 기준과 별도로
사용자가 방문 전부터 관람 이후까지 어떤 경험을 하는지 보기 위해
경험 단계를 네 가지로 정리한다.

```text
준비
↓
시선
↓
체험
↓
기억
```

---

## 7.1 준비

### 의미

관람 방식을 이해하고 현장 경험을 준비한다.

### 주요 경험

- 서비스 이해
- 이용 방법 확인
- 언어 / 접근성 확인

### 주요 터치포인트

**웹**

---

## 7.2 시선

### 의미

선택한 페르소나의 관점으로
실제 경복궁 공간과 역사를 이해한다.

### 주요 경험

- 왕 / 왕비 / 세자 페르소나 선택
- 현재 전각 확인
- 페르소나별 공간 해석
- 역사적 사건 확인
- 핵심 지점 확인

### 주요 터치포인트

**스마트 글라스**

---

## 7.3 체험

### 의미

공간에서 이해한 내용을
직접 행동하며 경험한다.

### 주요 경험

- 선택
- 조작
- 쓰기
- 배치
- 결과 확인

### 주요 터치포인트

**인터랙티브 스크린**

---

## 7.4 기억

### 의미

현장에서 만든 경험을 기록하고
관람 이후에도 다시 떠올릴 수 있게 한다.

### 주요 경험

- 완료 프로그램 확인
- 개인 체험 결과 확인
- 경험한 주요 공간 확인
- 관람 기록 다시 보기
- 커스텀 굿즈 선택 구매
- 일상에서 경험 다시 떠올리기

### 주요 터치포인트

**웹 + 커스텀 굿즈**
# 8. 서비스를 두 가지 기준으로 정리

경험 단계 기준을 추가한다고 해서
기존 터치포인트 구조를 없애는 것은 아니다.

## 터치포인트 기준

```text
웹
스마트 글라스
인터랙티브 스크린
커스텀 굿즈
```

> **어디에서 무엇을 제공하는가?**

각 접점의 기능과 역할을 구체적으로 설계할 때 사용한다.

## 경험 단계 기준

```text
준비
→ 시선
→ 체험
→ 기억
```

> **사용자가 어떤 과정을 경험하는가?**

방문 전부터 관람 이후까지 전체 경험을 하나의 흐름으로 볼 때 사용한다.

### 정리

> **궁온은 터치포인트 기준으로 기능과 역할을 구체화하고,
> 경험 단계 기준으로 사용자의 전체 관람 경험을 함께 정리한다.**
# 9. 서비스 원칙

궁온의 기능과 화면을 결정할 때  
다음 5개 원칙을 기준으로 판단한다.

---

## 원칙 01. 모든 경험은 실제 공간에서 시작한다

**궁온의 모든 정보와 체험은 실제 경복궁 공간과 연결되어야 한다.**

궁온은 화면 안에서 역사를 보여주는 서비스가 아니라,  
사용자가 지금 보고 있는 실제 공간을 더 잘 이해하고 경험하도록 돕는 서비스다.

### 적용 기준

- 제공하는 정보는 현재 보고 있는 공간과 연결한다.
- 역사적 사건은 실제 해당 공간을 바라보며 경험하게 한다.
- 핵심 지점은 실제 건축물이나 공간에서 확인할 수 있어야 한다.
- 체험 프로그램도 해당 공간의 역사적 기능과 연결한다.
- 실제 공간과 관계없는 콘텐츠는 핵심 경험에서 제외한다.

### 판단 질문

> **이 경험이 지금 보고 있는 실제 경복궁 공간과 연결되어 있는가?**

---

## 원칙 02. 정보를 나열하지 않고, 바라보는 관점을 제공한다

**같은 공간도 누구의 시선으로 보느냐에 따라 다르게 이해할 수 있게 한다.**

궁온은 역사 정보를 많이 보여주는 것보다,  
사용자가 공간을 어떤 기준으로 바라볼지 알려주는 것을 중요하게 본다.

스마트 글라스의 정보는 다음 세 가지로 구분한다.

```text
인물
누구의 시선으로 볼 것인가

+

사건
이 공간에서 무슨 일이 있었는가

+

핵심 지점
무엇을 주목해서 볼 것인가
```

### 적용 기준

- 단순한 역사 정보 나열로 끝내지 않는다.
- 선택한 페르소나과 공간의 관계를 먼저 보여준다.
- 역사적 사건은 현재 보고 있는 공간과 연결한다.
- 핵심 지점을 통해 실제로 무엇을 봐야 하는지 알려준다.

### 판단 질문

> **이 정보가 사용자가 공간을 바라보는 방식을 바꿔주는가?**

---

## 원칙 03. 이해한 내용은 직접 체험으로 이어진다

**보고 이해한 공간의 의미를 직접 행동하며 경험한다.**

스마트 글라스에서 공간을 이해한 뒤  
인터랙티브 스크린에서는 그 공간과 연결된 행동을 직접 수행한다.

```text
본다
↓
이해한다
↓
직접 체험한다
↓
결과가 남는다
```

### 적용 기준

- 스마트 글라스에서 설명을 보고 끝나지 않는다.
- 체험은 해당 공간의 역사적 기능과 연결한다.
- 선택 · 쓰기 · 배치 · 조작처럼 사용자가 직접 행동하게 한다.
- 단순 퀴즈나 영상 시청만으로 체험을 구성하지 않는다.
- 사용자의 행동에 따라 결과가 만들어지도록 한다.

### 판단 질문

> **이 체험이 방금 이해한 공간의 의미를 직접 느끼게 하는가?**

---

## 원칙 04. 각 경험은 끊기지 않고 이어진다

**한 접점에서 만든 경험과 결과가 다음 단계로 자연스럽게 이어져야 한다.**

웹, 스마트 글라스, 인터랙티브 스크린을  
각각 따로 사용하는 기기로 보지 않고  
하나의 관람 흐름 안에서 연결한다.

```text
웹
서비스 이해

↓

스마트 글라스
공간 해석

↓

인터랙티브 스크린
직접 체험

↓

웹
관람 기록

↓

커스텀 굿즈 [선택]
실물로 확장

↓

일상
경험 다시 떠올리기
```

### 적용 기준

- 웹에서 이해한 내용이 현장 경험으로 이어진다.
- 스마트 글라스의 공간 이해가 인터랙티브 스크린의 체험으로 이어진다.
- 인터랙티브 스크린의 결과가 웹의 관람 기록으로 이어진다.
- 관람 기록은 관람 후에도 다시 확인할 수 있다.
- 같은 기능을 여러 기기에서 반복하지 않는다.
- 다음 단계로 이동해야 하는 이유를 사용자가 이해할 수 있어야 한다.

### 판단 질문

> **이 경험이 끝난 뒤 사용자는 다음에 무엇을 해야 하는지 자연스럽게 알 수 있는가?**

---

## 원칙 05. 관람 방식은 사용자가 선택한다

**궁온이 정해진 체험을 강요하지 않고, 사용자가 자신의 속도와 방식으로 관람할 수 있게 한다.**

궁온은 모든 콘텐츠를 완료해야 하는 게임이 아니다.  
사용자는 필요한 경험을 선택하면서 실제 경복궁 관람을 이어갈 수 있다.

### 적용 기준

- 프로그램 참여를 강제하지 않는다.
- 모든 공간 방문을 요구하지 않는다.
- 프로그램을 건너뛰어도 관람을 계속할 수 있다.
- 굿즈 구매를 서비스 완료 조건으로 만들지 않는다.
- 점수 경쟁을 만들지 않는다.
- 엽전이나 스탬프 수집을 사용하지 않는다.
- 특정 순서대로 모든 경험을 완료하도록 강제하지 않는다.

### 판단 질문

> **사용자가 원하지 않는 경험까지 하도록 강요하고 있지는 않은가?**

```text
01 전체 이야기
이상적으로 어떤 경험을 하는가

02 주요 흐름
실제로 어떤 순서로 사용하는가

03 문제 상황
흐름이 깨졌을 때 어떻게 대응하는가
```

# 11. 전체 이야기

경복궁을 방문하기 전 관람객은
궁온 웹에서 서비스와 이용 방법을 확인한다.

현장에 도착하면 스마트 글라스를 대여하고 착용한 뒤,
왕·왕비·세자 중 이번 관람에 사용할 페르소나를 선택한다.

새로운 전각에 들어오면 스마트 글라스가 현재 공간을 확인하고,
사용자는 실제 경복궁을 먼저 바라본다.

이후 스마트 글라스에서는

- 선택한 페르소나와 현재 공간의 관계
- 이 공간에서 실제로 있었던 역사적 사건
- 실제 공간에서 주목해서 볼 핵심 지점

을 순서대로 확인한다.

대표 프로그램이 있는 공간에서는
왜 이 공간에서 이 체험을 하는지 짧게 안내한 뒤
참여 여부를 사용자가 선택한다.

참여를 선택하면 인터랙티브 스크린에서
선택·조작·쓰기·배치와 같은 행동을 직접 수행하고,
사용자의 행동이 반영된 개인 결과를 만든다.

대표 프로그램은

- 소주방의 **오늘의 수라상**
- 비현각의 **훈민정음 서재**

두 개로 운영한다.

체험 결과는 웹의 `나의 관람 기록`에 남고,
사용자는 다시 실제 경복궁 관람으로 돌아간다.

관람을 마치고 스마트 글라스를 반납한 뒤,
원하는 사용자는 현장에서 자신의 결과가 적용된 커스텀 굿즈를 확인하고
선택적으로 구매할 수 있다.

관람 이후에는 웹에서

- 선택한 페르소나
- 경험한 주요 공간
- 완료한 프로그램
- 개인 체험 결과

를 다시 확인한다.

웹의 기록과 선택적으로 구매한 굿즈는
현장에서의 경험을 관람 이후 다시 떠올릴 수 있게 한다.

# 14. 문제 상황과 대응

## 14.1 스마트 글라스가 공간을 인식하지 못함

```text
공간 인식 실패
↓
잘못된 내용 제공하지 않음
↓
기본 관람 상태 유지
↓
재인식 시도
↓
계속 실패하면 최소 안내 제공
```

### 원칙

> **확실하지 않은 역사 정보를 임의로 제공하지 않는다.**

---

## 14.2 인터랙티브 스크린이 사용 중

### 대응

- 기다림을 강제하지 않음
- 프로그램을 건너뛰고 관람 가능
- 원하는 경우 이후 다시 참여 가능

### 원칙

> **프로그램 때문에 전체 경복궁 관람이 멈추지 않도록 한다.**

---

## 14.3 사용자가 프로그램을 원하지 않음

```text
프로그램 안내
↓
참여 / 건너뛰기
↓
건너뛰기
↓
스마트 글라스 관람 지속
```

프로그램은 필수 미션이 아니다.

---

## 14.4 프로그램 체험 도중 중단

- 완료된 것으로 표시하지 않음
- 미완성 결과를 완성 결과처럼 저장하지 않음
- 재시작 가능 여부는 프로그램별로 정함

---

## 14.5 프로그램 결과가 웹에 보이지 않음

```text
프로그램 완료
↓
결과 생성
↓
시스템 저장
↓
관람 세션과 결과 연결
↓
웹 관람 기록 반영
```

사용자가 웹과 스마트 글라스를 직접 연결하거나 관리하는 기능은 만들지 않는다.

다만 여러 접점의 결과를 하나의 관람 기록으로 묶기 위한  
**관람 세션 식별 방식**은 운영 설계에서 정해야 한다.

---

## 14.6 스마트 글라스 장비 오류

```text
오류 확인
↓
현장 직원 지원
↓
필요 시 장비 교체
↓
기존 관람 기록 유지 여부 확인
```

---

## 14.7 굿즈를 구매하지 않음

아무런 불이익이 없다.

웹의 관람 기록만으로 서비스 경험은 완결된다.

선택적으로 구매하는 상품이다.

# 18. 스마트 글라스 페르소나

선택 가능한 페르소나는 세 개로 제한한다.

- 왕
- 왕비
- 세자

## 선택 시점

페르소나는 웹에서 미리 선택하지 않는다.

```text
스마트 글라스 착용
↓
왕 / 왕비 / 세자 확인
↓
페르소나별 관람 관점 확인
↓
페르소나 선택
↓
관람 시작
```

페르소나는 게임 캐릭터가 아니라
**이번 관람에서 경복궁을 어떤 관점으로 바라볼지를 정하는 기능**이다.

역사적 사실 자체가 페르소나에 따라 달라지는 것은 아니며,
달라지는 것은 공간을 바라보는 관점과 정보의 우선순위다.

# 22. 스마트 글라스 운영 원칙

1. 1인칭 시점을 유지한다.
2. 왕 / 왕비 / 세자만 선택할 수 있다.

5. 긴 역사 설명보다 핵심 내용을 우선한다.
6. 역사적 사실은 검수된 내용을 기반으로 한다.
7. 공간 관람을 방해하지 않는 최소한의 방향 안내만 제공한다.

두 프로그램으로 축소했다.

두 프로그램 모두

```text
공간 이해
→ 직접 행동
```

# 29. 터치포인트 사이 연결

궁온에서는 각 터치포인트가 무엇을 하는지만큼
**한 터치포인트에서 만들어진 경험이 다음 단계에서 어떻게 이어지는지**가 중요하다.

---

## 29.1 웹 → 스마트 글라스

### 이어지는 경험

**서비스 이해 → 현장 경험**

웹에서 서비스와 이용 방법을 이해한 뒤
현장에서 스마트 글라스 경험을 시작한다.

### 핵심 문장

> **이용 방법을 이해하고 현장으로**

이 연결은 기기를 직접 연결하는 것이 아니라
관람 전 이해한 이용 방식이 실제 현장 경험으로 이어지는 관계를 의미한다.

---

## 29.2 스마트 글라스 → 인터랙티브 스크린

### 이어지는 경험

**공간 이해 → 직접 행동**

스마트 글라스에서

- 현재 공간
- 페르소나별 공간 해석
- 역사적 사건
- 핵심 지점

을 이해한 뒤,
인터랙티브 스크린에서 그 공간과 연결된 행동을 직접 수행한다.

### 핵심 문장

> **공간의 이해를 행동으로**

---

## 29.3 인터랙티브 스크린 → 웹

### 이어지는 경험

**행동 → 개인 결과 → 기록**

인터랙티브 스크린에서 만든 결과가
웹의 관람 기록으로 이어진다.

### 이어지는 정보

- 프로그램 이름
- 완료 상태
- 개인 체험 결과

### 핵심 문장

> **체험 결과를 기록으로**

---

## 29.4 스마트 글라스 → 웹

### 이어지는 경험

**현장 관람 → 관람 기록**

웹에서 확인 가능한 내용:

- 선택한 페르소나
- 경험한 주요 공간
- 완료한 프로그램

전체 이동 경로나 실시간 위치 추적은
핵심 기록에 포함하지 않는다.

### 핵심 문장

> **경험한 공간과 페르소나를 기록으로**

---

## 29.5 인터랙티브 스크린 → 커스텀 굿즈

### 이어지는 경험

**개인 체험 결과 → 개인화된 실물**

굿즈의 주된 경로는 웹에서 시작하지 않는다.
현장에서 만든 개인 결과가
현장 굿즈의 개인화 정보로 이어진다.

```text
개인 체험 결과
↓
굿즈 적용 모습 확인
↓
실물 확인
↓
선택 구매
```

### 핵심 문장

> **체험 결과를 실물로**

---

## 29.6 웹 / 커스텀 굿즈 → 일상

### 이어지는 경험

**관람 경험 → 다시 떠올리기**

웹 기록이나 굿즈를 다시 접하면서
관람 이후에도 현장의 경험을 떠올릴 수 있다.

### 핵심 문장

> **현장의 경험을 일상으로**
# 30. 터치포인트 연결 전체 구조

```text
웹
서비스 이해

│
│ 이용 방법을 이해하고 현장으로
▼

스마트 글라스
페르소나 선택
+
실제 공간 이해

│
│ 공간의 이해를 행동으로
▼

인터랙티브 스크린
직접 행동
+
개인 체험 결과

        ↙                  ↘

웹                       커스텀 굿즈
관람 기록                 [선택]
기본 경로                 실물 확장

        ↓                  ↓

관람 이후                일상에서 사용

        ↘                  ↙

          기억 이어가기
```

웹 기록과 커스텀 굿즈는
인터랙티브 스크린의 개인 결과 이후 나뉘는 구조다.

굿즈를 구매하지 않아도
웹 관람 기록만으로 궁온의 기본 경험은 완성된다.
# 31. 경험 확장

궁온에서 말하는 경험 확장은
기능이나 프로그램을 계속 추가하는 것을 의미하지 않는다.

> **경복궁 현장에서 만들어진 개인의 경험이 관람 이후에도 기록과 결과의 형태로 남아 이어지는 것**

을 의미한다.

## 확장되는 내용

```text
페르소나
→ 어떤 관점으로 관람했는가

공간
→ 어떤 주요 공간을 경험했는가

프로그램
→ 무엇을 직접 했는가

개인 결과
→ 무엇을 만들었는가
```

## 두 가지 확장 경로

```text
개인 체험 결과

        ↙                  ↘

웹                       커스텀 굿즈
관람 기록                 선택형 실물 확장
기본 경로                 선택 경로

        ↘                  ↙

          기억 이어가기
```

웹 기록은 모든 사용자가 경험을 이어가는 기본 경로이고,
커스텀 굿즈는 원하는 사용자가 선택하는 실물 확장이다.
# 32. 커스텀 굿즈

커스텀 굿즈는 체험 완료 보상이 아니다.

## 정의

> **사용자가 현장에서 만든 개인의 체험 결과를 실물로 남기고 싶을 때 선택적으로 구매하는 상품**

## 사용할 수 있는 정보

- 선택한 페르소나
- 완료한 프로그램
- 프로그램 결과
- 방문 날짜
- 훈민정음 서재에서 작성한 글씨
- 오늘의 수라상에서 선택한 음식 / 상차림

상품마다 필요한 정보만 선택해 사용한다.

---

## 주요 경로 — 현장 구매

```text
프로그램 체험
↓
개인 체험 결과 완성
↓
현장 굿즈 공간
↓
결과 적용 모습 확인
↓
실물 확인
↓
구매 여부 선택
↓
개인화 굿즈 제작
```

현장 구매를 궁온의 주된 굿즈 경험으로 한다.

---

## 보조 경로 — 웹 구매

관람 당시 구매하지 않았지만
이후 다시 구매하고 싶은 사용자를 위한 보조 경로다.

```text
관람 이후
↓
웹 관람 기록
↓
이전 체험 결과 확인
↓
굿즈 다시 보기
↓
온라인 선택 구매
```

온라인 구매 자체를 기억 이어가기 기능으로 정의하지 않는다.

---

## 사용하지 않는 보상 구조

```text
체험 완료
→ 엽전 획득
→ 수집
→ 굿즈 교환
```

사용하지 않는다.

```text
체험 완료
→ 디지털 스탬프
→ 스탬프 수집
→ 무료 굿즈
```

사용하지 않는다.

### 현재 기준

- 실물 엽전 없음
- 디지털 스탬프 없음
- 무료 굿즈 없음
- 완료 보상형 굿즈 없음
- 굿즈 구매는 선택 사항
- 굿즈를 구매하지 않아도 서비스 경험은 완성됨
# 33. NFC 관련 기준

굿즈를 통해 관람을 다시 떠올리는 방향은 유지한다.

다만

**굿즈 NFC → 웹에서 과거 관람 기록 다시 열기**

기능은 현재 핵심 기능으로 확정하지 않는다.

필요한 경우 이후 선택 기능으로 검토한다.

---

# 34. 서비스 운영 구조

서비스 운영 구조에서는
사용자가 보는 경험과 그 경험이 실제로 작동하기 위해 필요한 운영을 함께 본다.

3주차에서는 모든 운영 절차를 세세하게 확정하기보다
핵심 경험이 실제로 이어지는 데 필요한 구조를 확인한다.

## 현장 핵심 운영 구조

| 단계 | 사용자 행동 | 사용자에게 보이는 서비스 | 필요한 운영 |
|---|---|---|---|
| 방문 전 | 서비스 확인 | 웹 이용 안내 | 서비스 정보 관리 |
| 현장 시작 | 글라스 대여·착용 | 현장 안내 | 장비 점검·대여 |
| 페르소나 선택 | 왕·왕비·세자 선택 | 페르소나 선택 화면 | 선택 정보 유지 |
| 공간 관람 | 실제 공간 확인 | 현재 전각 정보 | 공간 인식 |
| 공간 해석 | 내용 확인 | 페르소나별 공간 해석·역사적 사건·핵심 지점 | 역사 콘텐츠 연결·관리 |
| 직접 체험 | 선택·조작·쓰기·배치 | 체험 화면과 피드백 | 사용자 입력·결과 생성 |
| 결과 확인 | 개인 결과 확인 | 결과 화면 | 결과 저장 |
| 관람 종료 | 글라스 반납 | 반납 안내 | 장비 회수·점검 |
| 현장 굿즈 [선택] | 개인화 상품 확인 | 결과 적용 모습·실물 | 결과와 상품 정보 연결 |
| 관람 이후 | 기록 다시 보기 | 웹 관람 기록 | 현장 결과 연결·유지 |

## 운영에서 중요한 기준

- 역사 정보는 전문가 검수 내용을 기준으로 한다.
- 검수되지 않은 역사적 사실을 임의로 제공하지 않는다.
- 디지털 기능에 문제가 생겨도 실제 경복궁 관람은 계속할 수 있어야 한다.
- 프로그램과 굿즈 참여 여부는 사용자가 선택한다.

# 36. 관람 세션과 데이터 연결

사용자 입장에서는  
웹, 스마트 글라스, 인터랙티브 스크린이 서로 다른 기기지만

서비스 안에서는 하나의 관람 경험으로 이어져야 한다.

```text
관람 세션 시작
↓
페르소나 선택
↓
공간 경험
↓
프로그램 체험
↓
프로그램 결과
↓
관람 기록
↓
굿즈 미리보기
```

사용자가 직접 웹과 스마트 글라스를 연결하는 방식은 사용하지 않는다.

다만 내부적으로 결과를 한 사람의 기록에 연결할 방법은 필요하다.

---

# 37. 현재 추가로 정해야 할 항목

## 37.1 관람 세션 식별 방식

스마트 글라스와 인터랙티브 스크린에서 만들어진 결과를
한 방문객의 웹 기록으로 연결하기 위한 내부 방식은 아직 미확정이다.

후보:

- 이용권에 연결된 코드
- 임시 관람 코드
- 웹 계정
- 현장 발급 번호

### 기준

사용자가 웹과 스마트 글라스를 직접 연결하는
복잡한 과정은 만들지 않는다.

---

## 37.2 경험한 공간 기록 범위

현재 방향은

> **궁온 콘텐츠를 실제로 경험한 주요 공간 중심으로 기록**

하는 것이다.

전체 위치 이동 경로는 기록하지 않는다.

---

## 37.3 관람 이후 다시 떠올리기 방식

현재 확정:

- 웹에서 관람 기록 다시 확인
- 선택한 경우 커스텀 굿즈를 통해 일상에서 다시 떠올리기

현재 확정하지 않음:

- 별도의 알림 발송
- 정기적인 다시 보기 안내

---

## 37.4 굿즈 개인화 범위

상품마다 필요한 정보만 선택해 사용한다.

- 페르소나
- 프로그램 결과
- 방문 날짜
- 작성한 글씨
- 선택한 음식 / 상차림

---

## 37.5 대표 프로그램 장비 배치

대표 프로그램과 연결되는 경복궁 공간은 다음과 같이 정리한다.

```text
오늘의 수라상
→ 소주방

훈민정음 서재
→ 비현각
```

따라서 프로그램이 어느 전각과 연결되는지는 정해져 있다.

다만 해당 공간 안에서
인터랙티브 스크린과 체험 장비를 정확히 어느 위치에 배치할지는
현장 운영 가능성과 문화유산 보존 조건을 확인하며 이후 구체화한다.
# 38. 오류 대응 기본 원칙

디지털 기능에 문제가 발생해도  
실제 경복궁 관람은 계속할 수 있어야 한다.

### 스마트 글라스

- 배터리 부족
- 네트워크 문제
- 공간 인식 실패
- 화면 표시 오류
- 일시적인 사용 중단

### 인터랙티브 스크린

- 장비 오류
- 입력 오류
- 결과 저장 실패
- 사용자 중도 이탈

### 웹

- 네트워크 오류
- 관람 기록 불러오기 실패
- 결과 연결 실패

### 핵심

> **디지털 경험이 실제 경복궁 관람을 막는 구조가 되어서는 안 된다.**

# 39. 역사 콘텐츠 운영 원칙

궁온은 역사 문화유산을 다루는 서비스이므로  
콘텐츠 정확성을 우선한다.

다음 내용은 전문가 검수를 전제로 한다.

- 왕 / 왕비 / 세자 관련 정보
- 전각별 역사적 기능
- 역사적 사건
- 역사 장면
- 오늘의 수라상
- 훈민정음 서재

인공지능는 검수된 정보를 기반으로

- 선택
- 구성
- 요약
- 정보 우선순위
- 표현 방식

을 조정한다.

인공지능가 역사적 사실을 임의로 만들지 않는다.

## 40.1 1차 검증
### 실제 관람 문제와 현재 해결안 연결 확인

### 검증 질문

> **기존 관람에서 발견한 문제가 현재 궁온의 경험 구조와 직접 연결되어 있는가?**

| 실제 관람에서 확인한 문제 | 필요한 경험 | 현재 해결안 |
|---|---|---|
| 실제 공간과 역사 설명이 충분히 연결되지 않음 | 실제 공간과 역사 내용을 함께 이해 | 페르소나별 공간 해석 + 역사적 사건 |
| 무엇을 중심으로 봐야 할지 어려움 | 관람 기준과 주목 지점 | 페르소나 선택 + 핵심 지점 |
| 읽고 듣는 방식 중심 | 직접 행동 | 오늘의 수라상 + 훈민정음 서재 |
| 현장 경험이 각각 따로 끝남 | 경험 결과의 연결과 기록 | 스마트 글라스 → 인터랙티브 스크린 → 웹 |
| 관람 이후 경험이 끊김 | 기록과 다시 떠올리기 | 웹 기록 + 선택형 커스텀 굿즈 |

### 현재 상태

**문제와 해결안의 연결 관계를 1차로 점검한 상태**

아직 실제 사용자를 대상으로 한 검증이 완료된 것은 아니다.

# 44. 검증 결과 정리 방식

실제 사용자 검증 이후에는  
단순히 “좋았다 / 불편했다”로 정리하지 않는다.

| 발견한 문제 | 관찰한 근거 | 원인 | 수정 방향 |
|---|---|---|---|
| 예: Screen 사용 시점을 모름 | 사용자가 다음 행동에서 멈춤 | Glass → Screen 연결 안내 부족 | 프로그램 도착 안내 강화 |
| 예: 인물 해석과 역사 사건을 같은 정보로 인식 | 두 정보의 차이를 설명하지 못함 | 정보 역할 구분 부족 | 화면 구조와 제목 차이 강화 |
| 예: 체험 결과 위치를 찾지 못함 | 웹에서 여러 메뉴 탐색 | 결과 저장 안내 부족 | 체험 완료 시 기록 위치 안내 |

검증 이후에는

```text
프로토타입
↓
사용자 검증
↓
문제 확인
↓
수정
↓
재검증
```

과정을 반복한다.

# 48. 최종 기획 기준 요약

1. 실제 경복궁이 경험의 중심이다.
2. 화면보다 실제 공간을 먼저 본다.
3. 페르소나는 공간을 바라보는 관점을 제공한다.
4. 페르소나 기능은 왕 / 왕비 / 세자 세 가지로 구성한다.
5. 페르소나 선택은 스마트 글라스에서 진행한다.
6. 스마트 글라스는 1인칭 관람을 기준으로 한다.
7. 공간 해석은 `페르소나별 공간 해석 · 역사적 사건 · 핵심 지점`으로 구분한다.
8. 이해한 내용은 인터랙티브 스크린의 직접 행동으로 이어진다.
9. 대표 프로그램은 `오늘의 수라상 · 훈민정음 서재` 두 개로 운영한다.
10. 오늘의 수라상은 소주방, 훈민정음 서재는 비현각과 연결한다.
11. 역사 정보는 전문가 검수를 기반으로 한다.
12. 프로그램 참여는 선택 사항이다.
13. 웹은 안내 · 현황 · 기록을 중심으로 한다.
14. 현장 결과는 웹 기록과 선택형 커스텀 굿즈로 이어진다.
15. 커스텀 굿즈는 현장 구매를 중심으로 하며 무료 보상이 아니다.
16. 디지털 기능에 문제가 생겨도 실제 경복궁 관람은 계속할 수 있어야 한다.
# 49. 브랜드 정리

## 브랜드명

**궁온 / GUNG:ON**

## 브랜드 핵심

**시선**

궁온의 경험은
어떤 페르소나를 선택하고 어떤 관점에서 경복궁을 바라보는지에서 시작한다.

## 대표 문구

> **시선을 따라, 궁을 만나다.**

## 브랜드 한 줄 설명

> **페르소나의 시선으로 경복궁을 바라보고, 공간과 연결된 행동을 직접 경험하는 관람 서비스**

## 브랜드 핵심어

**시선 · 공간 · 경험 · 연결**

## 로고 방향

궁궐의 형태를 그대로 그리기보다

- 공간을 바라보는 틀
- 문과 창의 구조
- 전각의 선
- 겹쳐지는 관점
- 과거와 현재의 연결

을 활용해 궁온의 `시선`을 표현한다.

## 글자체 방향

### 브랜드 표현

**마루부리 우선 검토**

대표 문구, 주요 제목, 프로그램 이름, 포스터, 굿즈에 활용한다.

### 화면 정보

**프리텐다드 우선 검토**

웹, 스마트 글라스, 인터랙티브 스크린의 본문과 안내 정보에 활용한다.

현재는 방향을 정한 단계이며
실제 적용 후 최종 확정한다.

# 51. VER 2.0 기준 우선순위

앞으로 기존 문서와 VER 2.0의 내용이 충돌할 경우
이 문서의 최신 내용을 우선한다.

특히 아래 내용은 다시 사용하지 않는다.

- 웹 ↔ 스마트 글라스 직접 연결
- 스마트 글라스 연결 상태 확인
- 지도 중심 관람
- 전체 위치 추적
- 인공지능 동선 추천
- 실물 엽전
- 디지털 스탬프
- 무료 굿즈
- 스마트 글라스 3인칭
- 왕 / 왕비 / 세자 외 추가 페르소나
- 체험 완료 보상형 굿즈

스마트 글라스의 핵심 구조는 다음을 기준으로 한다.

```text
페르소나별 공간 해석
누구의 관점으로 볼 것인가

+

역사적 사건
이 공간에서 무슨 일이 있었는가

+

핵심 지점
무엇을 주목해서 볼 것인가
```

경험 구조는 다음을 기준으로 한다.

```text
준비
→ 시선
→ 체험
→ 기억
```

커스텀 굿즈는

```text
현장 체험 결과
→ 현장 굿즈 확인
→ 선택 구매
```

를 주된 경로로 하며,
웹 구매는 관람 이후의 보조 경로로 둔다.
